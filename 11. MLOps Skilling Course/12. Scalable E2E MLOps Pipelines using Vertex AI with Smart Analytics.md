# Scalable E2E MLOps Pipelines using Vertex AI with Smart Analytics

## Overview

In Session 4 you trained AutoML with one call from a script. That is fine once, but nobody can rerun exactly what you did, there is no record of which data made which model, and "retrain when data changes" means "remember to run the script". In this session you build a **Vertex AI Pipeline**: a repeatable chain of steps that pulls data from **BigQuery**, adds features, trains with AutoML, checks quality, and deploys **only if** the model is good enough.

By the end, you will be able to:

- Load a dataset into BigQuery, where an organisation's analytics data usually lives.
- Write pipeline **components** with the Kubeflow Pipelines (KFP) SDK and wire them into a **DAG**.
- Add a quality gate so deployment happens only above a threshold.
- Test component logic on your laptop before paying for a cloud run.
- Compile, submit and debug a pipeline run in Vertex AI.

**Prerequisites:** Python 3.11, the [`gcloud` CLI](https://cloud.google.com/sdk/docs/install), and Session 4. Steps 1–7 are free and run locally. **Steps 8–12 need a Google Cloud project with billing enabled**: one AutoML node-hour, BigQuery storage, and an endpoint billed per hour. Do Step 12 (clean up) the same day.

**Dataset:** [UCI Online Shoppers Purchasing Intention](https://archive.ics.uci.edu/dataset/468), 12,330 e-commerce sessions with 17 behaviour features (pages visited, time per page type, bounce and exit rates, month, visitor type, weekend) and `Revenue`: did the session end in a purchase? Only 15.5% did. It is downloaded automatically by the code.

### Words you will meet

| Term | Meaning |
| --- | --- |
| **Component** | One step (a Python function) that runs in its own container |
| **Pipeline / DAG** | Components connected by their inputs and outputs. DAG = directed acyclic graph: steps flow one way, no loops |
| **Artifact** | A file a component produces for the next one (a dataset, a model, metrics) |
| **Pipeline root** | The Cloud Storage folder where artifacts are stored between steps |
| **Compile** | Turn the Python pipeline into a JSON file Vertex AI can run |

## Step 3: Write the components (pipeline/components.py)

Each `@dsl.component` function becomes one container step. Everything a component needs must be imported **inside** the function and listed in `packages_to_install`, because it runs in a fresh, empty container, not in your venv.

```python
"""The five steps of the pipeline. Each one runs in its own container on Vertex AI."""
from kfp import dsl
from kfp.dsl import Dataset, Input, Metrics, Model, Output


@dsl.component(base_image="python:3.11",
               packages_to_install=["google-cloud-bigquery==3.26.0", "db-dtypes==1.3.0",
                                    "pandas==2.2.3"])
def extract_from_bigquery(project: str, bq_table: str, sessions: Output[Dataset]):
    from google.cloud import bigquery

    df = bigquery.Client(project=project).query(f"SELECT * FROM `{bq_table}`").to_dataframe()
    df.to_csv(sessions.path, index=False)
    print(f"extracted {len(df)} rows from {bq_table}")


@dsl.component(base_image="python:3.11", packages_to_install=["pandas==2.2.3"])
def engineer_features(sessions: Input[Dataset], features: Output[Dataset]):
    import pandas as pd

    df = pd.read_csv(sessions.path)
    df["total_pages"] = df["Administrative"] + df["Informational"] + df["ProductRelated"]
    total_seconds = (df["Administrative_Duration"] + df["Informational_Duration"]
                     + df["ProductRelated_Duration"])
    df["seconds_per_page"] = (total_seconds / df["total_pages"].clip(lower=1)).round(2)
    df["Weekend"] = df["Weekend"].astype(int)
    df["Revenue"] = df["Revenue"].astype(int)
    df.to_csv(features.path, index=False)
    print(f"{df.shape[1] - 1} input columns, {len(df)} rows")


@dsl.component(base_image="python:3.11",
               packages_to_install=["google-cloud-aiplatform==1.71.1"])
def train_automl(project: str, region: str, features: Input[Dataset],
                 model: Output[Model], metrics: Output[Metrics]):
    from google.cloud import aiplatform

    aiplatform.init(project=project, location=region)
    dataset = aiplatform.TabularDataset.create(
        display_name="shopper-sessions", gcs_source=[features.uri])
    job = aiplatform.AutoMLTabularTrainingJob(
        display_name="shopper-purchase-automl",
        optimization_prediction_type="classification",
        optimization_objective="maximize-au-prc",
    )
    trained = job.run(dataset=dataset, target_column="Revenue",
                      budget_milli_node_hours=1000,
                      model_display_name="shopper-purchase-model")
    au_prc = list(trained.list_model_evaluations())[0].metrics["auPrc"]
    metrics.log_metric("au_prc", au_prc)
    model.metadata["resource_name"] = trained.resource_name
    print(f"trained {trained.resource_name}, AU PRC {au_prc:.4f}")


@dsl.component(base_image="python:3.11")
def check_quality(metrics: Input[Metrics], threshold: float) -> str:
    au_prc = metrics.metadata["au_prc"]
    decision = "deploy" if au_prc >= threshold else "skip"
    print(f"AU PRC {au_prc:.4f} vs threshold {threshold}: {decision}")
    return decision


@dsl.component(base_image="python:3.11",
               packages_to_install=["google-cloud-aiplatform==1.71.1"])
def deploy_model(project: str, region: str, model: Input[Model]):
    from google.cloud import aiplatform

    aiplatform.init(project=project, location=region)
    trained = aiplatform.Model(model.metadata["resource_name"])
    endpoint = aiplatform.Endpoint.create(display_name="shopper-purchase-endpoint")
    trained.deploy(endpoint=endpoint, machine_type="n1-standard-4", min_replica_count=1)
    print(f"deployed to {endpoint.resource_name}")
```

| Component | Input | Output | What it does |
| --- | --- | --- | --- |
| `extract_from_bigquery` | table name | `sessions` CSV | Runs a SQL query on BigQuery |
| `engineer_features` | `sessions` | `features` CSV | Adds `total_pages` and `seconds_per_page`; turns booleans into 0/1 |
| `train_automl` | `features` | `model`, `metrics` | AutoML training, optimising **AU PRC** |
| `check_quality` | `metrics`, threshold | `"deploy"` or `"skip"` | The quality gate |
| `deploy_model` | `model` | an endpoint | Runs only if the gate says `deploy` |

Details worth noticing:

- **`Output[Dataset]` / `Input[Dataset]`** are artifacts. KFP gives each one a `path` (a local file inside the container) and a `uri` (its place in the pipeline root on Cloud Storage). You write to `path`; the next component reads it.
- **`train_automl` hands AutoML `features.uri`**, the `gs://` address of the engineered CSV. No extra upload step.
- **`maximize-au-prc`, not `minimize-log-loss` as in Session 4.** Only 15.5% of sessions buy. AU PRC (area under the precision-recall curve) focuses on how well the model finds that rare class. Choosing the wrong objective does not raise an error; AutoML simply optimises the wrong thing.
- **We do not one-hot encode `Month` or `VisitorType`.** AutoML detects text columns and encodes them itself.
- **Pinned versions inside `packages_to_install`.** An unpinned package in a component installs whatever is newest on the day it runs, the same problem `requirements.txt` solves for your laptop.

## Step 4: Choose a threshold with a local baseline (src/baseline.py)

A quality gate needs a number. Pick it from evidence, not from a guess.

```python
"""A local model with the same features, to choose a sensible AU PRC threshold."""
import pandas as pd
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score
from sklearn.model_selection import train_test_split
from ucimlrepo import fetch_ucirepo

df = fetch_ucirepo(id=468).data.original
print(f"{len(df)} sessions, purchase rate {df['Revenue'].mean():.3f}")

df["total_pages"] = df["Administrative"] + df["Informational"] + df["ProductRelated"]
total_seconds = (df["Administrative_Duration"] + df["Informational_Duration"]
                 + df["ProductRelated_Duration"])
df["seconds_per_page"] = (total_seconds / df["total_pages"].clip(lower=1)).round(2)
X = pd.get_dummies(df.drop(columns=["Revenue"]), columns=["Month", "VisitorType"])
y = df["Revenue"].astype(int)

X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.15, random_state=42, stratify=y)
model = HistGradientBoostingClassifier(random_state=42).fit(X_tr, y_tr)
print(f"random guess AU PRC   : {y_te.mean():.3f}")
print(f"local baseline AU PRC : {average_precision_score(y_te, model.predict_proba(X_te)[:, 1]):.3f}")
```

```bash
python -m src.baseline
```

```text
12330 sessions, purchase rate 0.155
random guess AU PRC   : 0.155
local baseline AU PRC : 0.746
```

A model that guesses at random scores AU PRC equal to the purchase rate (0.155). A ten-line local model scores 0.746. So **0.70** is a sensible bar: an AutoML model below it is worse than what we can build for free, and should not reach production. (Accuracy would be useless here: always predicting "no purchase" is already 84.5% accurate.)

## Step 5: Wire the pipeline and compile it (pipeline/pipeline.py)

```python
"""Wire the components into a DAG and compile it to shopper_pipeline.json."""
from kfp import compiler, dsl

from pipeline.components import (
    check_quality,
    deploy_model,
    engineer_features,
    extract_from_bigquery,
    train_automl,
)


@dsl.pipeline(name="shopper-purchase-pipeline")
def purchase_pipeline(project: str, region: str, bq_table: str,
                      au_prc_threshold: float = 0.70):
    extract = extract_from_bigquery(project=project, bq_table=bq_table)
    engineer = engineer_features(sessions=extract.outputs["sessions"])
    train = train_automl(project=project, region=region,
                         features=engineer.outputs["features"])
    quality = check_quality(metrics=train.outputs["metrics"], threshold=au_prc_threshold)
    with dsl.If(quality.output == "deploy", name="deploy-if-good-enough"):
        deploy_model(project=project, region=region, model=train.outputs["model"])


if __name__ == "__main__":
    compiler.Compiler().compile(purchase_pipeline, package_path="shopper_pipeline.json")
    print("compiled shopper_pipeline.json")
```

- **The order comes from the data, not from the line order.** `engineer` uses `extract.outputs["sessions"]`, so it runs after `extract`. These references are the edges of the DAG.
- **`dsl.If`** makes deployment conditional. `check_quality` returns a plain string, available as `quality.output`. If it is `"skip"`, the deploy step never runs: a correct outcome, not an error.

```bash
python -m pipeline.pipeline
```

```text
compiled shopper_pipeline.json
```

Compiling checks the wiring for free. A typo in an output name, or a type mismatch between components, fails here, not 40 minutes into a cloud run.

## Step 6: Test the components on your laptop (tests/test\_components.py)

Every component keeps its plain Python function in `.python_func`. You can call it directly with local files, no container and no cloud.

```python
"""Run the plain Python inside two components on a laptop, without Vertex AI."""
import pandas as pd
from kfp.dsl import Dataset, Metrics

from pipeline.components import check_quality, engineer_features


def test_engineer_features_adds_columns_and_makes_ints(tmp_path):
    raw = pd.DataFrame({
        "Administrative": [2, 0], "Administrative_Duration": [40.0, 0.0],
        "Informational": [0, 0], "Informational_Duration": [0.0, 0.0],
        "ProductRelated": [8, 0], "ProductRelated_Duration": [160.0, 0.0],
        "Weekend": [True, False], "Revenue": [False, True],
    })
    raw.to_csv(tmp_path / "in.csv", index=False)
    out = Dataset(uri=str(tmp_path / "out.csv"))

    engineer_features.python_func(sessions=Dataset(uri=str(tmp_path / "in.csv")), features=out)

    df = pd.read_csv(out.path)
    assert df["total_pages"].tolist() == [10, 0]
    assert df["seconds_per_page"].tolist() == [20.0, 0.0]   # no divide-by-zero
    assert df["Weekend"].tolist() == [1, 0]
    assert df["Revenue"].tolist() == [0, 1]


def test_check_quality_deploys_only_above_threshold():
    good, bad = Metrics(uri="unused"), Metrics(uri="unused")
    good.log_metric("au_prc", 0.80)
    bad.log_metric("au_prc", 0.60)
    assert check_quality.python_func(metrics=good, threshold=0.70) == "deploy"
    assert check_quality.python_func(metrics=bad, threshold=0.70) == "skip"
```

```bash
python -m pytest -v
```

```text
2 passed
```

The second row of the first test is a session with **zero pages**. Without `.clip(lower=1)`, it would divide by zero and write `inf` into the training data. Finding that in a 1-second local test is much cheaper than finding it in a failed cloud run.

```bash
python -m src.submit
```

`submit()` returns as soon as Vertex AI **accepts** the job. Open **Vertex AI → Pipelines** in the console and click the run. You see the DAG:

```text
extract-from-bigquery → engineer-features → train-automl → check-quality → [deploy-if-good-enough] → deploy-model
```

Each box turns green as it finishes. The whole run takes a little under an hour, almost all of it `train-automl`. Click any box to see its logs and its input and output artifacts.

**`enable_caching=True`**: if you submit again with the same inputs, steps that already succeeded are skipped and their stored outputs reused. After a failure in `train-automl`, a rerun goes straight back to the failed step instead of repeating the BigQuery extract.

## Step 10: When a step fails

A pipeline run that fails tells you **which box** failed. Click the red box and read its logs. Common ones:

| Failed step | Log says | Cause and fix |
| --- | --- | --- |
| any | `ModuleNotFoundError` | A package is missing from that component's `packages_to_install`. Add it, recompile, resubmit |
| `extract-from-bigquery` | `403 ... bigquery.jobs.create` | The service account lacks BigQuery roles (Step 7) |
| `extract-from-bigquery` | `404 Not found: Table` | `src.load_bigquery` not run, or `BQ_TABLE` typo |
| `train-automl` | `429 Quota exceeded for quota metric 'AutoML training ...'` | New projects start with small AutoML quotas. Request an increase in **IAM & Admin → Quotas**, then resubmit; caching skips the finished steps |
| `train-automl` | `PERMISSION_DENIED ... aiplatform` | The service account lacks `roles/aiplatform.user` |
| `deploy-model` box is grey, not red | – | Not a failure: the gate said `skip` (AU PRC below the threshold) |

To prove the gate really gates, set `AU_PRC_THRESHOLD = 0.99` in `config.py` and submit again. With caching, the run reuses the trained model, `check-quality` logs `skip`, and `deploy-model` stays grey.

## Step 11: Use the deployed model (src/predict.py)

```python
"""Find the endpoint the pipeline created (if it deployed) and score one session."""
from google.cloud import aiplatform

from src.config import PROJECT_ID, REGION

aiplatform.init(project=PROJECT_ID, location=REGION)
endpoints = aiplatform.Endpoint.list(filter='display_name="shopper-purchase-endpoint"',
                                     order_by="create_time desc")
if not endpoints:
    raise SystemExit("No endpoint: the quality gate decided not to deploy (or the run failed).")

# Raw columns plus the two engineered ones, computed exactly as engineer_features does.
session = {
    "Administrative": 2, "Administrative_Duration": 45.0,
    "Informational": 0, "Informational_Duration": 0.0,
    "ProductRelated": 34, "ProductRelated_Duration": 1200.5,
    "BounceRates": 0.01, "ExitRates": 0.02, "PageValues": 12.4, "SpecialDay": 0.0,
    "Month": "Nov", "OperatingSystems": 2, "Browser": 2, "Region": 1,
    "TrafficType": 2, "VisitorType": "Returning_Visitor", "Weekend": 1,
}
session["total_pages"] = (session["Administrative"] + session["Informational"]
                          + session["ProductRelated"])
seconds = (session["Administrative_Duration"] + session["Informational_Duration"]
           + session["ProductRelated_Duration"])
session["seconds_per_page"] = round(seconds / max(session["total_pages"], 1), 2)

instance = {k: str(v) for k, v in session.items()}      # AutoML wants strings
result = endpoints[0].predict(instances=[instance]).predictions[0]
for cls, score in zip(result["classes"], result["scores"]):
    print(f"Revenue={cls}: {score:.3f}")
```

```bash
python -m src.predict
```

The output is two lines, the scores for `Revenue=0` and `Revenue=1`. This session has a high `PageValues` (12.4), the strongest purchase signal in this dataset, so expect a high score for `1`.

**Training/serving skew.** The request must contain `total_pages` and `seconds_per_page`, computed **exactly** as `engineer_features` did. Here that logic is written twice, once in the component and once in `predict.py`. If someone changes one and not the other, the model gets inputs that mean something different from training, and nothing raises an error. Production systems avoid this by sharing one feature function between training and serving, or by using a feature store.

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `FileNotFoundError: shopper_pipeline.json` on submit | Pipeline not compiled | `python -m pipeline.pipeline` |
| Compile error: `... has no output named ...` | Typo in `outputs["..."]` | Use the parameter name from the component (`sessions`, `features`, `model`, `metrics`) |
| `DefaultCredentialsError` | Only `gcloud auth login` was run | Also `gcloud auth application-default login` |
| `ModuleNotFoundError` inside a step | Package not in that component's `packages_to_install` | Add it, recompile, resubmit |
| `403` in `extract-from-bigquery` | Service account lacks BigQuery roles | Grant the roles in Step 7 |
| `429 Quota exceeded` in `train-automl` | AutoML quota on a new project | Request an increase; resubmit (caching skips finished steps) |
| `predict` says "No endpoint" | The gate chose `skip`, or the run failed | Check the run's `check-quality` logs |
| `400` from `predict` about the input | Missing an engineered column, or a non-string value | Send every column, including `total_pages` and `seconds_per_page`, as strings |
