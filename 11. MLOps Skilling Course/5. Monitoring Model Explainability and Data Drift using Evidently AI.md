# Monitoring Model Explainability and Data Drift using Evidently AI

## Overview

A model's validation score is measured on data like its training data. Production data changes: new customer groups, new channels, new seasons. The model keeps answering with confidence, and nothing warns you. In this session you train a model on older bank data, run it on newer data, and use **Evidently AI** to detect the change, measure it per column, check whether the model's reasoning shifted, and turn it all into a pass/fail gate.

By the end, you will be able to:

- Split data into a **reference** window (what the model trained on) and a **current** window (what production sends).
- Produce an Evidently drift report as HTML (for people) and JSON (for code).
- Read drift scores correctly: some tests flag drift when the score is **high**, others when it is **low**.
- Compare prediction drift, label drift and feature importance between windows.
- Write a drift gate that exits with an error code, ready for a scheduled job or CI.

**Prerequisites:** Python 3.11 and a terminal. Everything runs locally.

**Dataset:** [UCI Bank Marketing](https://archive.ics.uci.edu/dataset/222/bank+marketing), 45,211 phone-campaign calls from a Portuguese bank, with 16 client and campaign features and the target `y`: did the client open a term deposit? The rows are in time order, and the bank changed how it ran its campaigns over those years, so the drift is real, not simulated. It is downloaded automatically by the code.

## Step 4: Load and split the data (src/data.py)

```python
"""Load UCI Bank Marketing and split it into a reference and a current window."""
import pandas as pd
from ucimlrepo import fetch_ucirepo

CAT_COLS = ["job", "marital", "education", "default", "housing",
            "loan", "contact", "month", "poutcome"]
NUM_COLS = ["age", "balance", "day_of_week", "duration",
            "campaign", "pdays", "previous"]
FEATURES = NUM_COLS + CAT_COLS
TARGET = "y"


def load_windows():
    df = fetch_ucirepo(id=222).data.original
    # The bank fills these with NaN; make "unknown" an explicit category.
    df[CAT_COLS] = df[CAT_COLS].fillna("unknown")
    n = len(df)
    reference = df.iloc[: int(0.60 * n)].reset_index(drop=True)   # oldest 60%
    current = df.iloc[int(0.75 * n):].reset_index(drop=True)      # newest 25%
    return reference, current


def encode(frame, columns=None):
    X = pd.get_dummies(frame[FEATURES], columns=CAT_COLS)
    if columns is not None:
        X = X.reindex(columns=columns, fill_value=0)
    return X


def label(frame):
    return (frame[TARGET] == "yes").astype(int)
```

What each part does:

- **Time split.** Rows are in time order, so the first 60% is "the past the model trained on" and the last 25% is "production now". The 15% gap in between stands for a model that was trained a while ago and has been running since.
- **`fillna("unknown")`.** `contact` (13,020 rows), `poutcome`, `education` and `job` have missing values. `pd.get_dummies` silently ignores missing values, so without this line "contact unknown" would not exist as a feature at all, even though it carries real information.
- **`encode(..., columns)`.** One-hot encoding turns `contact` into `contact_cellular`, `contact_telephone`, `contact_unknown`. If a category vanishes in the current window, encoding it on its own would produce a different set of columns. `reindex` forces the training columns, filling missing ones with 0. Misaligned columns give wrong predictions without any error, which is far worse than a crash.

import joblib
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import train_test_split

print(f"encoded features: {X_ref.shape[1]}")

X_tr, X_val, y_tr, y_val = train_test_split(
    X_ref, y_ref, test_size=0.2, random_state=42, stratify=y_ref
)
model = HistGradientBoostingClassifier(max_iter=200, random_state=42)
model.fit(X_tr, y_tr)

val_auc = roc_auc_score(y_val, model.predict_proba(X_val)[:, 1])
print(f"validation ROC AUC (reference window): {val_auc:.4f}")

joblib.dump({"model": model, "columns": list(X_ref.columns), "val_auc": val_auc},
            "model.joblib")

## Step 6: Measure the real damage (src/score.py)

Before any drift tool, check whether there is a real problem. We can do this here only because this dataset has labels for the current window. In production, labels arrive weeks or months later.

```python
"""Score the saved model on the current window, where we happen to have labels."""
import joblib
from sklearn.metrics import roc_auc_score

from src.data import encode, label, load_windows

saved = joblib.load("model.joblib")
model, columns = saved["model"], saved["columns"]
reference, current = load_windows()

X_cur, y_cur = encode(current, columns), label(current)
cur_scores = model.predict_proba(X_cur)[:, 1]
cur_auc = roc_auc_score(y_cur, cur_scores)

print(f"ROC AUC on reference hold-out : {saved['val_auc']:.4f}")
print(f"ROC AUC on current window     : {cur_auc:.4f}")
print(f"change                        : {cur_auc - saved['val_auc']:+.4f}")
print()
print(f"positive rate, reference      : {label(reference).mean():.4f}")
print(f"mean predicted prob, current  : {cur_scores.mean():.4f}")
print(f"actual positive rate, current : {y_cur.mean():.4f}")
```

## Step 7: The data drift report (src/drift\_report.py)

Give Evidently a reference and a current table. For each column it picks a statistical test, runs it, and says whether that column drifted.

```python
"""Run Evidently's data drift report and print the per-column results."""
import json

import pandas as pd
from evidently import ColumnMapping
from evidently.metric_preset import DataDriftPreset
from evidently.report import Report

from src.data import CAT_COLS, NUM_COLS, TARGET, load_windows

COLUMN_MAPPING = ColumnMapping(
    target=TARGET,
    prediction=None,
    numerical_features=NUM_COLS,
    categorical_features=CAT_COLS,
)


def run_drift(reference, current):
    report = Report(metrics=[DataDriftPreset()])
    report.run(reference_data=reference, current_data=current,
               column_mapping=COLUMN_MAPPING)
    return report


def main():
    reference, current = load_windows()
    report = run_drift(reference, current)
    report.save_html("reports/drift_report.html")
    result = report.as_dict()
    with open("reports/drift_report.json", "w") as f:
        json.dump(result, f, indent=2, default=str)

    summary = result["metrics"][0]["result"]
    print(f"columns analysed : {summary['number_of_columns']}")
    print(f"columns drifted  : {summary['number_of_drifted_columns']}")
    print(f"share drifted    : {summary['share_of_drifted_columns']:.3f}")
    print(f"dataset drift    : {summary['dataset_drift']}")
    print()

    by_column = result["metrics"][1]["result"]["drift_by_columns"]
    table = pd.DataFrame([
        {"column": name,
         "stat_test": info["stattest_name"],
         "drift_score": round(info["drift_score"], 4),
         "threshold": info["stattest_threshold"],
         "drifted": info["drift_detected"]}
        for name, info in by_column.items()
    ]).sort_values(["stat_test", "column"])
    print(table.to_string(index=False))


if __name__ == "__main__":
    main()
```

**`ColumnMapping`** tells Evidently which columns are numbers, which are categories, and which is the target. Without it, Evidently guesses, and it often guesses wrong for categories stored as integers.

Open `reports/drift_report.html` in a browser. Each column has a chart overlaying its reference and current distributions. Look at `contact`: about half the reference calls were `unknown` and half `cellular`; in the current window, 88% are `cellular` and `unknown` has almost disappeared. The bank switched to mobile-first calling.

How to read the table:

- **Distance tests** (Jensen-Shannon for categories, Wasserstein for numbers) measure **how far apart** the two distributions are. **Higher = more drift.** Drift is flagged above 0.1.
- **"Dataset drift: True"** is a rule, not a measurement: more than half the columns drifted. One critical column can drift while the rest hold steady and the banner stays green. Always look at the columns your model depends on.
- **`y` drifted (0.23).** The share of "yes" answers changed. That matches the 5% → 28% we saw in Step 6, but in real life you would only see this row once labels arrive.
- **`duration` did not drift (0.09).** Remember this; it matters in Step 10.

## Step 8: The score can mean the opposite (src/small\_sample.py)

Evidently chooses the test from the data. With more than 1,000 rows it uses distances. With 1,000 rows or fewer it switches to **p-value tests** (chi-square, Kolmogorov-Smirnov), and the score then works the other way round.

```python
"""Re-run the drift report on 500-row samples to see which tests Evidently picks."""
from src.data import load_windows
from src.drift_report import run_drift

reference, current = load_windows()
report = run_drift(reference.sample(500, random_state=0),
                   current.sample(500, random_state=0))
by_column = report.as_dict()["metrics"][1]["result"]["drift_by_columns"]
for name in ["contact", "marital", "pdays", "balance"]:
    info = by_column[name]
    print(f"{name:<8} {info['stattest_name']:<22} score={info['drift_score']:.4f} "
          f"threshold={info['stattest_threshold']}  drifted={info['drift_detected']}")
```

```bash
python -m src.small_sample
```

```text
contact  chi-square p_value     score=0.0000 threshold=0.05  drifted=True
marital  chi-square p_value     score=0.0000 threshold=0.05  drifted=True
pdays    K-S p_value            score=0.0000 threshold=0.05  drifted=True
balance  K-S p_value            score=0.0007 threshold=0.05  drifted=True
```

You may also see a `RuntimeWarning: divide by zero` from the chi-square test. It is harmless here.

| Test type | Example | Score means | Drift when score is |
| --- | --- | --- | --- |
| Distance | Jensen-Shannon, Wasserstein | How far apart the distributions are | **above** the threshold (0.1) |
| p-value | chi-square, K-S | How likely the difference is to be chance | **below** the threshold (0.05) |

**This is the most misread number in drift monitoring.** Sorting a table by `drift_score` to find "the worst column" gives nonsense when the table mixes both kinds of test. Use `drift_detected` for the yes/no answer, and compare scores only between columns that used the same test.

Note also that `marital` and `balance` are flagged here but were not flagged on the full data. P-value tests ask "is there *any* difference?", not "is the difference *big*?", so even a small shift gets a tiny p-value. Keeping the comparison windows a fixed size keeps your monitor's sensitivity stable from month to month.

## Step 9: Prediction drift and label drift (src/prediction\_drift.py)

Feature drift asks "did the inputs change?". **Prediction drift** asks "did our answers change?". **Label drift** asks "did the real outcome change?".

```python
"""Compare the model's predictions, and the labels, between the two windows."""
import joblib
from evidently.metrics import ColumnDriftMetric
from evidently.report import Report

from src.data import TARGET, encode, load_windows

saved = joblib.load("model.joblib")
model, columns = saved["model"], saved["columns"]
reference, current = load_windows()
reference["prediction"] = model.predict_proba(encode(reference, columns))[:, 1]
current["prediction"] = model.predict_proba(encode(current, columns))[:, 1]

report = Report(metrics=[
    ColumnDriftMetric(column_name="prediction"),   # available immediately
    ColumnDriftMetric(column_name=TARGET),         # needs labels, which arrive late
])
report.run(reference_data=reference[["prediction", TARGET]],
           current_data=current[["prediction", TARGET]])
report.save_html("reports/prediction_drift.html")

for metric in report.as_dict()["metrics"]:
    r = metric["result"]
    print(f"{r['column_name']:<11} test={r['stattest_name']:<30} "
          f"score={r['drift_score']:.4f}  drifted={r['drift_detected']}")
```

```bash
python -m src.prediction_drift
```

```text
prediction  test=Wasserstein distance (normed)  score=0.3201  drifted=True
y           test=Jensen-Shannon distance        score=0.2265  drifted=True
```

Prediction drift is your **early warning**: you can compute it the moment predictions are made. Label drift is the **confirmation** that arrives later. The four combinations mean different things:

| Features | Predictions | Labels | Meaning |
| --- | --- | --- | --- |
| drift | drift | drift | The population really changed and the model is reacting (this run). Retrain. |
| drift | stable | – | The drifted columns are ones the model ignores. Often safe. |
| stable | drift | – | Suspicious: inputs did not move but outputs did. Look for a pipeline bug. |
| stable | stable | drift | The worst case: the world changed and the model never noticed. Only labels catch it. |

## Step 10: Has the model's reasoning changed? (src/importance.py)

**Permutation importance** shuffles one feature at a time and measures how much AUC drops. A big drop means the model relies on that feature. Computing it on each window shows whether the model leans on the same features in production as in training.

```python
"""Has the model's reasoning changed? Permutation importance on each window."""
import joblib
import pandas as pd
from sklearn.inspection import permutation_importance
from sklearn.model_selection import train_test_split

from src.data import FEATURES, encode, label, load_windows

saved = joblib.load("model.joblib")
model, columns = saved["model"], saved["columns"]
reference, current = load_windows()

# The same validation rows train.py held out.
X_ref, y_ref = encode(reference, columns), label(reference)
_, X_val, _, y_val = train_test_split(X_ref, y_ref, test_size=0.2,
                                      random_state=42, stratify=y_ref)
X_cur, y_cur = encode(current, columns), label(current)


def importance(X, y):
    r = permutation_importance(model, X, y, n_repeats=5, random_state=0,
                               scoring="roc_auc", n_jobs=-1)
    per_column = pd.Series(r.importances_mean, index=X.columns)
    # Add the one-hot columns (contact_cellular, contact_unknown, ...) back together.
    return pd.Series({
        feat: per_column[[c for c in X.columns if c == feat or c.startswith(feat + "_")]].sum()
        for feat in FEATURES
    })


table = pd.DataFrame({"reference": importance(X_val, y_val),
                      "current": importance(X_cur, y_cur)})
table["change"] = table["current"] - table["reference"]
print(table.sort_values("reference", ascending=False).round(4).head(8).to_string())
```

This is the most useful result in the lab:

- **`duration` is by far the most important feature, and its importance halved.** Yet Step 7 said `duration` did **not** drift (0.09). Its distribution stayed the same, but its link to the outcome changed: a long call means something different now that 28% of people say yes. This is **concept drift**, and input drift reports cannot see it.
- **`month` became three times more important**, and it drifted strongly (0.40). The model now depends more on a feature whose values have moved away from what it learned.

So the input-only checks (Steps 7–9) did warn us, through `month`, `contact` and prediction drift, but they did not explain the full AUC drop. Only labels showed that the model's main feature stopped working.

`duration` is also **leaky**: you only know how long a call lasted after it ends, so it could not be used to decide whom to call. We keep it here because it makes the comparison clear (see Exercises).

## Step 11: Turn the checks into a pass/fail gate (src/gate.py)

Reports are for people investigating. A scheduled job needs a yes or no. Evidently's `TestSuite` gives each check an explicit condition and returns pass or fail.

```python
"""Pass/fail drift gate. Exits with code 1 when any test fails."""
import json
import sys
from datetime import date

from evidently.test_suite import TestSuite
from evidently.tests import TestColumnDrift, TestNumberOfMissingValues, TestShareOfDriftedColumns

from src.data import load_windows
from src.drift_report import COLUMN_MAPPING

reference, current = load_windows()

suite = TestSuite(tests=[
    TestNumberOfMissingValues(eq=0),
    TestShareOfDriftedColumns(lt=0.5),
    # The columns the model leans on most, checked one by one.
    TestColumnDrift(column_name="duration"),
    TestColumnDrift(column_name="month"),
    TestColumnDrift(column_name="contact"),
])
suite.run(reference_data=reference, current_data=current, column_mapping=COLUMN_MAPPING)
suite.save_html("reports/gate.html")

outcome = suite.as_dict()
passed = outcome["summary"]["all_passed"]
for test in outcome["tests"]:
    print(f"[{test['status']:<4}] {test['name']}: {test['description']}")

manifest = {
    "run_date": date.today().isoformat(),
    "reference_rows": len(reference),
    "current_rows": len(current),
    "tests_passed": sum(t["status"] == "SUCCESS" for t in outcome["tests"]),
    "tests_total": len(outcome["tests"]),
    "gate_passed": passed,
}
with open("reports/manifest.json", "w") as f:
    json.dump(manifest, f, indent=2)
print(json.dumps(manifest, indent=2))

sys.exit(0 if passed else 1)
```

Design choices worth copying:

- **Exit code 1 on failure.** A scheduler, cron job or CI pipeline (Session 10) treats any non-zero exit code as "failed" and can alert or block automatically.
- **Per-column tests for the important features.** The overall share can pass while the one column that matters drifts badly.
- **A missing-values test.** A sudden rise in nulls looks like drift and tempts you to retrain, when the real fix is a broken upstream system. Session 11 covers this side with Deepchecks.
- **`manifest.json`** is small and flat so it can be added to a table, one row per run. Add the AUC later when labels arrive, and you can plot drift against real performance over time. If the gate fails every week while AUC holds steady, your thresholds are too strict and the team will learn to ignore the alerts.

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `ImportError: cannot import name 'ColumnMapping' from 'evidently'` | Evidently 0.7 or newer installed | `pip install "evidently==0.4.40"`. Do not mix old and new import styles |
| `ModuleNotFoundError: No module named 'evidently.metric_preset'` | Same: Evidently 0.7+ | Same fix |
| `FileNotFoundError: model.joblib` | `train` has not been run | `python -m src.train` first |
| `FileNotFoundError: reports/...` | The `reports` folder is missing | `mkdir reports` |
| No `contact_unknown` column / missing-values test fails | Removed the `fillna("unknown")` line | Keep it: missing contact is information, not noise |
| HTML report opens as a blank page | Browser blocked local scripts | Open it in a different browser, or check the JSON instead |
| Every column drifts | Columns read with different types in the two windows (e.g. number vs text) | Check `reference.dtypes` against `current.dtypes` |
| Nothing drifts, but AUC falls | Concept drift: the link from inputs to outcome changed | Only labels can catch it; schedule a labelled AUC check |
| `ModuleNotFoundError: No module named 'src'` | Ran `python src/train.py` | Run `python -m src.train` |
