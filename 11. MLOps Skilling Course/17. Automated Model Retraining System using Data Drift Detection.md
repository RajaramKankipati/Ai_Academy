# Automated Model Retraining System using Data Drift Detection

## Overview

In Session 5, Evidently produced drift reports, and a person decided whether to retrain. In this session you remove the person from the routine case: a monitoring cycle measures drift on every new batch, **triggers retraining** when drift is confirmed, compares the new model with the current one on data neither has seen, and **promotes only a better model**. Everything is logged so a person can step in when the loop cannot decide.

```text
new batch ──► big enough? ──► PSI per feature ──► drift in 2 cycles in a row?
                                                          │ yes
                                                          ▼
                       retrain on (old training data + new batches)
                                                          │
                compare on unseen labelled data: better on recent data? not worse on old data?
                                  │ yes                                  │ no
                                  ▼                                      ▼
                          PROMOTE new version                 REJECT, flag for a human
```

By the end, you will be able to:

- Measure drift per feature with the Population Stability Index (PSI).
- Turn drift into a yes/no retraining trigger, with guards against false alarms.
- Measure how often a drift trigger fires on data that has **not** drifted.
- Promote a retrained model only if it beats the current one on unseen data, without getting worse on older data.
- Keep the loop's state and history in files a scheduler or a person can read.

**Prerequisites:** Python 3.11. Everything runs locally.

**Dataset:** [UCI Energy Efficiency](https://archive.ics.uci.edu/dataset/242/energy+efficiency), 768 simulated buildings described by 8 design features (compactness, surface/wall/roof area, height, orientation, glazing area and layout), with the heating load as target. There is no time axis, so we simulate a design trend: over time, more buildings are tall and glass-heavy. It is downloaded automatically by the code.

## Step 3: Data, pools and simulated batches (src/data.py)

```python
"""Load UCI Energy Efficiency and split it into baseline, future stream and evaluation pools."""
import numpy as np
from sklearn.model_selection import train_test_split

NAMES = {"X1": "compactness", "X2": "surface_area", "X3": "wall_area", "X4": "roof_area",
         "X5": "height", "X6": "orientation", "X7": "glazing_area", "X8": "glazing_layout",
         "Y1": "heating_load"}
FEATURES = list(NAMES.values())[:-1]
TARGET = "heating_load"


def load_pools():
    from ucimlrepo import fetch_ucirepo

    df = fetch_ucirepo(id=242).data.original.rename(columns=NAMES).drop(columns=["Y2"])
    baseline, rest = train_test_split(df, test_size=0.5, random_state=42)
    stream_pool, eval_pool = train_test_split(rest, test_size=0.5, random_state=42)
    return baseline, stream_pool, eval_pool


def stable_batch(pool, n, seed):
    return pool.sample(n=n, replace=True, random_state=seed).reset_index(drop=True)


def drifted_batch(pool, n, seed):
    """Design trend: more glass and taller buildings. Rows are drawn with weights."""
    weights = (pool["glazing_area"].rank(pct=True) * pool["height"].rank(pct=True)) ** 2
    rng = np.random.RandomState(seed)
    idx = rng.choice(pool.index, size=n, replace=True, p=(weights / weights.sum()).values)
    return pool.loc[idx].reset_index(drop=True)
```

- **Readable names.** UCI calls the columns `X1` … `X8`. It is easy to mix them up (`X5` is height, not glazing area, which is `X7`), so we rename them once.
- **Three separate pools:**

| Pool | Rows | Used for |
| --- | --- | --- |
| `baseline` | 384 | Training the first production model |
| `stream_pool` | 192 | Building the "new batches" that arrive over time |
| `eval_pool` | 192 | **Only** for comparing models. Never trained on |

The evaluation pool must be separate. If the comparison data overlapped the batch the new model was trained on, the new model would be marked on questions it had already seen, and it would "win" every time.

- **`drifted_batch`** picks rows with probability rising with glazing area and height, simulating a trend towards tall, glass-heavy designs.

## Step 4: PSI and the trigger (src/drift.py)

The **Population Stability Index** compares how a feature's values are spread across categories in the reference data and in the new batch. Conventional reading: below 0.1 no meaningful change, 0.1–0.25 moderate, above 0.25 significant.

```python
"""Population Stability Index per feature, and the retraining trigger."""
import numpy as np

PSI_THRESHOLD = 0.25
MIN_BATCH = 150


def psi(reference, current):
    """PSI over the distinct values of a feature (every feature here has 2-12 values)."""
    values = np.union1d(reference.unique(), current.unique())
    ref = reference.value_counts(normalize=True).reindex(values, fill_value=0).clip(lower=1e-4)
    cur = current.value_counts(normalize=True).reindex(values, fill_value=0).clip(lower=1e-4)
    return float(((cur - ref) * np.log(cur / ref)).sum())


def drift_check(reference, batch, features, threshold=PSI_THRESHOLD):
    scores = {f: round(psi(reference[f], batch[f]), 3) for f in features}
    drifted = {f: s for f, s in scores.items() if s > threshold}
    return {"scores": scores, "drifted": drifted, "triggered": bool(drifted)}
```

- **Every feature here takes only 2–12 distinct values** (height is 3.5 or 7.0; orientation 2, 3, 4 or 5). PSI is usually computed on 10 quantile bins, but with so few values the quantile edges coincide. We use each distinct value as its own bin instead.
- **`clip(lower=1e-4)`** avoids dividing by zero or taking `log(0)` when a value appears in one set but not the other.
- **PSI per feature** tells you *which* input changed, not just that something did. That lets a person check an alert against a known cause ("yes, the new client builds glass towers") before trusting it.
- **`MIN_BATCH = 150`**: Step 6 shows where this number comes from.

### tests/test\_drift.py

import pandas as pd

from src.drift import drift_check, psi


def test_identical_distributions_have_zero_psi():
    s = pd.Series([1, 2, 3, 1, 2, 3])
    assert psi(s, s) == 0


def test_a_new_value_that_takes_over_gives_high_psi():
    reference = pd.Series([3.5] * 50 + [7.0] * 50)
    current = pd.Series([7.0] * 95 + [3.5] * 5)
    assert psi(reference, current) > 0.25


def test_trigger_names_the_drifted_feature_only():
    reference = pd.DataFrame({"a": [1, 2] * 50, "b": [1, 2] * 50})
    batch = pd.DataFrame({"a": [1, 2] * 50, "b": [2] * 95 + [1] * 5})
    result = drift_check(reference, batch, ["a", "b"])
    assert result["triggered"] and list(result["drifted"]) == ["b"]

## Step 5: How often does the trigger lie? (src/noise.py)

Before trusting any automatic trigger, test it where you **know** the right answer is "no drift": many batches drawn from the very same population.

```python
"""How often does the trigger fire on batches with NO real drift? It depends on batch size."""
from src.data import FEATURES, load_pools, stable_batch
from src.drift import drift_check

baseline, stream_pool, _ = load_pools()
TRIALS = 200

print("batch size   false triggers   two in a row")
for size in [20, 50, 100, 150, 300]:
    fired = [drift_check(baseline, stable_batch(stream_pool, size, seed), FEATURES)["triggered"]
             for seed in range(TRIALS)]
    single = sum(fired) / TRIALS
    pairs = sum(a and b for a, b in zip(fired, fired[1:])) / (TRIALS - 1)
    print(f"{size:>10}   {single:>13.0%}   {pairs:>12.0%}")
```

```bash
python -m src.noise      # about 10 seconds
```

```text
batch size   false triggers   two in a row
        20            100%           100%
        50             84%            72%
       100             42%            18%
       150             22%             4%
       300              3%             0%
```

**This table is the most important result of the lab.** None of these batches drifted, yet:

- With **20 rows**, the trigger fires **every time**. A batch that small cannot fill 12 categories evenly, so PSI is always high.
- With **150 rows**, it still fires **22%** of the time, on pure noise.
- Requiring drift in **two cycles in a row** cuts the 150-row false alarms from 22% to **4%**.

Without these guards, an "automatic retraining system" retrains constantly on noise: wasted compute, and models fitted to random small samples. That is why the loop requires at least 150 rows (`MIN_BATCH`) and two consecutive triggers. The right values depend on your data; measure them like this before you trust a trigger.

## Step 7: One monitoring cycle (src/loop.py)

```python
"""One monitoring cycle: check a new batch for drift, retrain if needed, promote only if better.

Usage: python -m src.loop stable|drifted <seed> [batch_size]
"""
import json
import os
import sys
from datetime import datetime, timezone

import joblib
import pandas as pd
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error

from src.data import FEATURES, TARGET, drifted_batch, load_pools, stable_batch
from src.drift import MIN_BATCH, drift_check

CYCLES_TO_CONFIRM = 2       # drift must show up in 2 cycles in a row
MAX_HISTORICAL_LOSS = 0.05  # the new model may be at most 5% worse on historical data

kind, seed = sys.argv[1], int(sys.argv[2])
size = int(sys.argv[3]) if len(sys.argv) > 3 else 150
_, stream_pool, eval_pool = load_pools()
make = drifted_batch if kind == "drifted" else stable_batch
batch = make(stream_pool, size, seed)

state = json.load(open("state/loop.json"))
reference = pd.read_csv("state/reference.csv")
production = joblib.load("state/production.joblib")
log = {"time": datetime.now(timezone.utc).isoformat(timespec="seconds"),
       "batch": f"{kind}#{seed}", "rows": len(batch), "version": state["version"]}

if len(batch) < MIN_BATCH:
    log["action"] = f"skipped: batch smaller than {MIN_BATCH}"
else:
    check = drift_check(reference, batch, FEATURES)
    log["max_psi"] = max(check["scores"].values())
    log["drifted"] = sorted(check["drifted"])
    if not check["triggered"]:
        state["consecutive_triggers"] = 0
        log["action"] = "none"
        if os.path.exists("state/pending.csv"):
            os.remove("state/pending.csv")
    else:
        state["consecutive_triggers"] += 1
        pending = pd.concat([pd.read_csv("state/pending.csv"), batch]) \
            if os.path.exists("state/pending.csv") else batch
        pending.to_csv("state/pending.csv", index=False)
        if state["consecutive_triggers"] < CYCLES_TO_CONFIRM:
            log["action"] = f"drift seen ({state['consecutive_triggers']}/{CYCLES_TO_CONFIRM}), waiting"
        else:
            # Retrain on everything production knew, plus the confirmed new data.
            train = pd.concat([reference, pending], ignore_index=True)
            candidate = RandomForestRegressor(n_estimators=200, random_state=42)
            candidate.fit(train[FEATURES], train[TARGET])

            # Judge on labelled rows neither model has seen: recent-looking and historical-looking.
            recent = make(eval_pool, 150, seed + 1000)
            historical = stable_batch(eval_pool, 150, seed + 2000)
            mae = {name: {who: round(mean_absolute_error(data[TARGET], m.predict(data[FEATURES])), 3)
                          for who, m in [("production", production), ("candidate", candidate)]}
                   for name, data in [("recent", recent), ("historical", historical)]}
            log["mae"] = mae
            better_now = mae["recent"]["candidate"] < mae["recent"]["production"]
            no_forgetting = (mae["historical"]["candidate"]
                             <= mae["historical"]["production"] * (1 + MAX_HISTORICAL_LOSS))
            if better_now and no_forgetting:
                state["version"] += 1
                joblib.dump(candidate, "state/production.joblib")
                train.to_csv("state/reference.csv", index=False)
                log["action"] = f"PROMOTED v{state['version']} (trained on {len(train)} rows)"
            else:
                log["action"] = "REJECTED: candidate not better; flag for human review"
            state["consecutive_triggers"] = 0
            os.remove("state/pending.csv")

json.dump(state, open("state/loop.json", "w"))
with open("state/history.jsonl", "a") as f:
    f.write(json.dumps(log) + "\n")
print(json.dumps(log, indent=2))
```

What each part does:

- **Two guards before anything expensive**: skip batches under 150 rows, and wait for drift in two cycles in a row (Step 5). Drifted batches wait in `pending.csv`; a clean cycle in between resets the count and discards them.
- **Retrain on old + new data**, not the new batches alone. 300 rows of glass towers alone would make a model that forgets ordinary buildings, which still exist.
- **Two promotion conditions**, both measured on `eval_pool` rows that neither model trained on:
  1. **Better on recent data**: lower error on buildings like the new trend.
  2. **No forgetting**: at most 5% worse on historical-looking buildings.
- **A rejection is not an error.** It means the drift is real but retraining did not help; the recipe (features, model, data volume) needs a person. That is the case to alert on.
- **`history.jsonl`** gets one flat JSON line per cycle. A scheduler can append it to a table and page someone only on `REJECTED`, or when the trigger rate itself starts climbing.

Drift confirmed, so the loop retrains on 384 old + 300 new rows. On unseen recent-style buildings the error falls from 0.458 to **0.400** (13% better), and on historical-style buildings it does not get worse (0.410 → 0.401). Both conditions hold, so version 2 is promoted. Heating loads range from about 6 to 43 kWh/m², so both models are good; the gain is real but modest. Drift within the range of data the model has already seen hurts less than a model meeting something entirely new.

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `FileNotFoundError: state/loop.json` | Bootstrap not run | `python -m src.bootstrap` |
| PSI near zero for a feature that clearly changed | Quantile bins collapse when a feature has only a few distinct values | Use one bin per distinct value, as in `psi()` |
| Retraining fires almost every cycle | Batches too small, or no consecutive-cycle guard | Measure false alarms with `noise.py`; raise `MIN_BATCH`; keep `CYCLES_TO_CONFIRM = 2` |
| The new model always wins | Evaluation rows overlap the training batches | Evaluate only on `eval_pool`, kept apart from the start |
| New model better on new data, worse on old | Retrained on the new batches alone | Retrain on reference + pending; keep the no-forgetting check |
| `IndexError: list index out of range` | Missing arguments | `python -m src.loop drifted 2` |
