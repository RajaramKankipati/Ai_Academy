# Cloud-Based MLOps Pipeline using Google Cloud Vertex AI

## Overview

In Session 4, AutoML chose the model for you. In this session **you** write the training code, and Vertex AI runs it on managed machines as a **custom training job**. You package the training script in a container, run it in the cloud, get the trained model registered automatically in the **Model Registry**, deploy it to an endpoint and call it.

| | AutoML (Session 4) | Custom training (this session) |
| --- | --- | --- |
| Who picks the model | Vertex AI searches | You write the code |
| What you upload | A table | A container with your training script |
| Control | Little | Full: features, model, settings |
| After training | Model Registry → endpoint | The same Model Registry → endpoint |

By the end, you will be able to:

- Write one training script that runs unchanged on your laptop and in Vertex AI.
- Build a training container with Cloud Build and push it to Artifact Registry.
- Run a `CustomContainerTrainingJob` and find its model in the Model Registry.
- Match the training and serving library versions so the deployed model loads.
- Deploy, call and delete an endpoint.

**Prerequisites:** Python 3.11 and Sessions 4 and 6. Steps 1–5 are free and run locally. **Steps 6–11 need a Google Cloud project with billing enabled** and the [`gcloud` CLI](https://cloud.google.com/sdk/docs/install). You do **not** need Docker on your laptop: Cloud Build builds the image. Do Step 11 (clean up) the same day.

**Dataset:** [UCI Dry Bean](https://archive.ics.uci.edu/dataset/602/dry+bean+dataset), 13,611 beans photographed and reduced to 16 shape measurements (area, perimeter, roundness, ...), each labelled as one of 7 varieties. It is downloaded automatically by the code.

## Step 4: The training script (trainer/train.py)

```python
"""Train the bean classifier. Runs the same way on a laptop and as a Vertex AI custom job.

Inputs (environment variables):
  DATA_URI       a local path or gs:// path to DryBean.csv
  AIP_MODEL_DIR  where to write model.joblib (Vertex AI sets this to a gs:// folder)
"""
import os
import tempfile

import joblib
import pandas as pd
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import classification_report, f1_score
from sklearn.model_selection import train_test_split

DATA_URI = os.environ["DATA_URI"]
MODEL_DIR = os.environ["AIP_MODEL_DIR"]


def gcs_split(uri):
    bucket, _, path = uri.removeprefix("gs://").partition("/")
    return bucket, path


def read_csv(uri):
    if not uri.startswith("gs://"):
        return pd.read_csv(uri)
    from google.cloud import storage
    bucket, path = gcs_split(uri)
    local = os.path.join(tempfile.mkdtemp(), "data.csv")
    storage.Client().bucket(bucket).blob(path).download_to_filename(local)
    return pd.read_csv(local)


def save_model(model, model_dir):
    local = os.path.join(tempfile.mkdtemp(), "model.joblib")
    joblib.dump(model, local)
    if not model_dir.startswith("gs://"):
        os.makedirs(model_dir, exist_ok=True)
        os.replace(local, os.path.join(model_dir, "model.joblib"))
        return
    from google.cloud import storage
    bucket, path = gcs_split(model_dir.rstrip("/") + "/model.joblib")
    storage.Client().bucket(bucket).blob(path).upload_from_filename(local)


df = read_csv(DATA_URI)
X, y = df.drop(columns=["Class"]), df["Class"]
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

model = HistGradientBoostingClassifier(max_iter=200, learning_rate=0.1, random_state=42)
model.fit(X_tr.values, y_tr)            # plain arrays: the serving container sends plain arrays
pred = model.predict(X_te.values)
print(classification_report(y_te, pred, digits=3))
print(f"weighted F1: {f1_score(y_te, pred, average='weighted'):.4f}")

save_model(model, MODEL_DIR)
print(f"model written to {MODEL_DIR.rstrip('/')}/model.joblib")
```

What each part does:

- **Inputs come from environment variables, not hard-coded paths.** `AIP_MODEL_DIR` is set by Vertex AI for every custom job: it is where Vertex AI expects the model file, and how it knows what to register afterwards. Locally you set both variables yourself.
- **Local paths and `gs://` paths both work.** pandas cannot read `gs://` paths without an extra library (`gcsfs`), so the script uses `google-cloud-storage` to download and upload explicitly.
- **`fit(X_tr.values, ...)`**: the model is trained on plain number arrays, without column names, because the prebuilt serving container passes plain arrays to `predict()`.
- **The file must be named `model.joblib`**: the prebuilt serving container looks for exactly that name.

## Step 7: Build the training container with Cloud Build

### trainer/Dockerfile

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY train.py .
ENTRYPOINT ["python", "train.py"]
```

`ENTRYPOINT` is what Vertex AI runs when the job starts. Every version is pinned in `requirements.txt`, so the cloud run uses exactly the libraries your local run did.

Create the image repository and build. Cloud Build uploads the `trainer/` folder, builds the image on Google's machines and pushes it:

```bash
gcloud artifacts repositories create dry-bean --repository-format=docker --location=us-central1
gcloud builds submit trainer \
    --tag us-central1-docker.pkg.dev/your-gcp-project-id/dry-bean/trainer:v1
```

The build log ends with the image's `DIGEST` and `STATUS: SUCCESS`. Use a new tag (`v2`, `v3`, ...) for every change to the trainer, so you always know which code a job ran.

## Step 8: Run the custom training job (src/launch\_job.py)

```python
"""Run trainer/ as a Vertex AI custom training job and register the result as a model."""
from google.cloud import aiplatform

from src.config import BUCKET_URI, IMAGE_URI, PROJECT_ID, REGION, SERVING_IMAGE

aiplatform.init(project=PROJECT_ID, location=REGION, staging_bucket=BUCKET_URI)

job = aiplatform.CustomContainerTrainingJob(
    display_name="dry-bean-custom-training",
    container_uri=IMAGE_URI,                         # runs train.py
    model_serving_container_image_uri=SERVING_IMAGE,  # serves model.joblib afterwards
)
model = job.run(
    replica_count=1,
    machine_type="n1-standard-4",
    environment_variables={"DATA_URI": f"{BUCKET_URI}/data/DryBean.csv"},
    base_output_dir=f"{BUCKET_URI}/training-output",
    model_display_name="dry-bean-classifier",
)
print(f"model: {model.resource_name}  version {model.version_id}")
print(f"serving image: {model.container_spec.image_uri}")
```

- **Two different images, on purpose.** `container_uri` is **your** training image: it runs `train.py` once and exits. `model_serving_container_image_uri` is Google's prediction server: it runs for as long as the endpoint exists, loads `model.joblib` and answers HTTP requests.
- **`base_output_dir`**: Vertex AI sets `AIP_MODEL_DIR` to a `model/` folder under it. That is where `train.py` writes.
- **`model_display_name`**: because a serving image was given, the job **registers** the model in the Model Registry when training finishes.

```bash
python -m src.launch_job
```

The script prints a console link and waits. The job takes about 10 minutes, most of it starting the machine. In the console (**Vertex AI → Training**), open the job and click **View logs**: you see your own script's `classification_report`, proof that your code ran, not something cached. The script finishes with:

```text
model: projects/123456789/locations/us-central1/models/987654321  version 1
serving image: us-docker.pkg.dev/vertex-ai/prediction/sklearn-cpu.1-3:latest
```

If the serving image line shows **your training image** instead, the model would be registered with a container that cannot serve predictions.

If the logs show a Python traceback from `train.py`, fix it and rerun **Step 5 locally** before rebuilding; do not debug by relaunching cloud jobs.

## Step 9: Deploy (src/deploy.py)

```python
"""Deploy the newest dry-bean-classifier model to a new endpoint."""
from google.cloud import aiplatform

from src.config import PROJECT_ID, REGION

aiplatform.init(project=PROJECT_ID, location=REGION)
model = aiplatform.Model.list(filter='display_name="dry-bean-classifier"',
                              order_by="create_time desc")[0]
endpoint = aiplatform.Endpoint.create(display_name="dry-bean-endpoint")
model.deploy(endpoint=endpoint, deployed_model_display_name="dry-bean-v1",
             machine_type="n1-standard-2", min_replica_count=1, max_replica_count=2)
print(f"endpoint: {endpoint.resource_name}")
```

```bash
python -m src.deploy       # about 10-15 minutes
```

`max_replica_count=2` lets the endpoint add a second machine under load. Autoscaling means the bill varies with traffic; check the endpoint's metrics in the console if a bill looks high.

## Step 10: Get predictions (src/predict.py)

```python
"""Send three real beans to the endpoint and compare with their true classes."""
import pandas as pd
from google.cloud import aiplatform

from src.config import PROJECT_ID, REGION

aiplatform.init(project=PROJECT_ID, location=REGION)
endpoint = aiplatform.Endpoint.list(filter='display_name="dry-bean-endpoint"')[0]

df = pd.read_csv("data/DryBean.csv")
rows = df.iloc[[0, 5000, 13000]]
# The sklearn serving container wants plain lists of numbers, in training column order.
instances = rows.drop(columns=["Class"]).values.tolist()
print("predicted:", endpoint.predict(instances=instances).predictions)
print("actual:   ", rows["Class"].tolist())
```

```bash
python -m src.predict
```

Expected output. The local model from Step 5 gives exactly these answers for the same three beans, and the cloud model is trained on the same data with the same seed:

```text
predicted: ['SEKER', 'CALI', 'DERMASON']
actual:    ['SEKER', 'CALI', 'DERMASON']
```

Compare with Session 4:

- **Request format.** AutoML endpoints take a dict of strings per row. The prebuilt scikit-learn container takes a **plain list of numbers per row**, in training column order. Sending dicts gives a `400` error.
- **Response.** AutoML returned a score for every class. The scikit-learn container calls `predict()` and returns only the label. To return probabilities you need your own serving container (as in Session 6) or a Vertex AI custom prediction routine.

## Step 11: Clean up (do not skip)

### src/cleanup.py

```python
"""Undeploy and delete the endpoint so it stops billing."""
from google.cloud import aiplatform

from src.config import PROJECT_ID, REGION

aiplatform.init(project=PROJECT_ID, location=REGION)
for endpoint in aiplatform.Endpoint.list(filter='display_name="dry-bean-endpoint"'):
    endpoint.undeploy_all()
    endpoint.delete()
    print(f"deleted {endpoint.resource_name}")
```

```bash
python -m src.cleanup
gcloud artifacts repositories delete dry-bean --location=us-central1 --quiet
```

Custom training has a billing surface AutoML did not: **stored container images** in Artifact Registry. They cost little, but they do not show up under "Vertex AI" in a quick look at the bill. Check **Vertex AI → Online prediction → Endpoints** and **Artifact Registry** in the console.

### Turning this into a pipeline

The steps above run one by one. To rerun them identically on a schedule, wrap them in a Vertex AI Pipeline as in Session 12: a component that launches this training job, a component that evaluates the new model against the current one, and a conditional deploy. Google's `google-cloud-pipeline-components` package provides ready-made components for custom jobs and model upload.

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `KeyError: 'DATA_URI'` locally | Environment variables not set | `DATA_URI=... AIP_MODEL_DIR=... python trainer/train.py` |
| `ImportError ... gcsfs` reading `gs://` with pandas | pandas cannot read Cloud Storage on its own | Download with `google-cloud-storage`, as `read_csv()` does |
| Job fails at start: image not found / `PERMISSION_DENIED` pulling | Wrong `IMAGE_URI`, or image not pushed | Compare `config.py` with `gcloud artifacts docker images list ...` |
| Job log shows a traceback from `train.py` | Bug in your script | Reproduce and fix with Step 5 locally, then rebuild with a new tag |
| No model registered after the job | `model_serving_container_image_uri` or `model_display_name` missing, or `model.joblib` not written to `AIP_MODEL_DIR` | Check both arguments and the "model written to" log line |
| Endpoint fails to start; logs mention unpickling | Trained with a scikit-learn other than 1.3.x | Keep `scikit-learn==1.3.2` in `trainer/requirements.txt` |
| `400` on predict | Sent dicts or strings | Send `[[16 numbers], ...]` in training column order |
| `ResourceExhausted ... quota` on job or deploy | Not enough CPU quota in the region | Request more in **IAM & Admin → Quotas**, or use a smaller machine type |
