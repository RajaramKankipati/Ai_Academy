# Versioning and Tracking ML Models using MLflow

## Overview

You will train three versions of a wine-quality model, log every run to **MLflow**, compare the runs side by side, and register the best one in the **MLflow Model Registry** so other code can load it by name.

By the end, you will be able to:

- Start a local MLflow tracking server and open its web UI.
- Log parameters, metrics and the trained model for every training run.
- Compare runs in the UI and from Python.
- Register a model, give it the `champion` alias, and load it by that alias.

**Prerequisites:** Python 3.11 and a terminal. No cloud account is needed.

**Dataset:** [UCI Wine Quality](https://archive.ics.uci.edu/dataset/186/wine+quality). We use the 1,599 red wines: 11 lab measurements (acidity, sugar, alcohol, ...) and a quality score from tasters. It is downloaded automatically by the code.

Why MLflow? Without it, you keep a spreadsheet of which settings gave which score, and hunt through folders for the matching model file. MLflow records every run (settings in, scores out, the model file itself) automatically, and keeps it all searchable.


### src/data.py

```python
"""Load the UCI Wine Quality dataset (red wines only) and split it."""
from sklearn.model_selection import train_test_split
from ucimlrepo import fetch_ucirepo

RANDOM_STATE = 42


def load_red_wine():
    ds = fetch_ucirepo(id=186)
    df = ds.data.original
    df = df[df["color"] == "red"].drop(columns=["color"]).reset_index(drop=True)
    X = df.drop(columns=["quality"])
    y = df["quality"]
    return X, y


def load_split():
    X, y = load_red_wine()
    return train_test_split(X, y, test_size=0.2, random_state=RANDOM_STATE)
```

What each part does:

- **`fetch_ucirepo(id=186)`** downloads 6,497 wines, red and white together. The `color` column says which is which.
- **`df["color"] == "red"`** keeps the 1,599 red wines. A smaller dataset keeps every training run to a few seconds.
- **`load_split()`** puts 20% of the wines aside for testing. `random_state=42` makes the split the same on every run. **Every run must use the same split**; otherwise a better score might just mean easier test rows, not better settings.

## Step 6: Log a training run (src/train.py)

```python
"""Train one random forest and log the run to MLflow.

Usage: python -m src.train <n_estimators> <max_depth|none> <run_name>
"""
import sys

import mlflow
import mlflow.sklearn
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

from src.config import EXPERIMENT_NAME, TRACKING_URI
from src.data import RANDOM_STATE, load_split


def main(n_estimators, max_depth, run_name):
    mlflow.set_tracking_uri(TRACKING_URI)
    mlflow.set_experiment(EXPERIMENT_NAME)
    X_train, X_test, y_train, y_test = load_split()

    with mlflow.start_run(run_name=run_name) as run:
        mlflow.log_param("n_estimators", n_estimators)
        mlflow.log_param("max_depth", max_depth)
        mlflow.log_param("model_type", "RandomForestRegressor")

        model = RandomForestRegressor(
            n_estimators=n_estimators, max_depth=max_depth, random_state=RANDOM_STATE
        )
        model.fit(X_train, y_train)
        preds = model.predict(X_test)

        mae = mean_absolute_error(y_test, preds)
        rmse = mean_squared_error(y_test, preds) ** 0.5
        r2 = r2_score(y_test, preds)
        mlflow.log_metric("mae", mae)
        mlflow.log_metric("rmse", rmse)
        mlflow.log_metric("r2", r2)
        mlflow.sklearn.log_model(model, artifact_path="model", input_example=X_test.head(2))

        print(f"{run_name}: mae={mae:.4f} rmse={rmse:.4f} r2={r2:.4f} "
              f"run_id={run.info.run_id}")


if __name__ == "__main__":
    n = int(sys.argv[1])
    depth = None if sys.argv[2].lower() == "none" else int(sys.argv[2])
    main(n, depth, sys.argv[3])
```

What each part does:

- **`set_tracking_uri`** sends everything to the server from Step 4. **`set_experiment`** creates the experiment the first time and reuses it after that.
- **`with mlflow.start_run(...)`** opens one run. Every `log_*` call inside the `with` block is attached to that run.
- **`log_param`** records the settings (inputs). **`log_metric`** records the scores (outputs).
- **MAE** (mean absolute error): on average, how many quality points the prediction is off by. Lower is better. **R²**: share of the variation the model explains; 1.0 is perfect.
- **`log_model`** uploads the trained model itself, so you never have to hunt for the file. `input_example` saves two sample rows with it, which records the expected input columns.

## Step 7: Launch three runs

Three settings, from a deliberately small, shallow forest to a large, unlimited one:

```bash
python -m src.train 10 3 shallow-small-forest
python -m src.train 100 8 medium-forest
python -m src.train 300 none large-unbounded-forest
```

Expected output (one line per run; the run IDs will differ):

```text
shallow-small-forest: mae=0.5349 rmse=0.6505 r2=0.3524 run_id=43dcf3d5...
medium-forest: mae=0.4586 rmse=0.5746 r2=0.4949 run_id=60ac6f38...
large-unbounded-forest: mae=0.4238 rmse=0.5536 r2=0.5311 run_id=3e474560...
```

Notice that going from small to medium cuts the error a lot (0.53 → 0.46), while going from medium to large helps much less (0.46 → 0.42). This is **diminishing returns**: each extra tree helps less than the one before.

Keep in mind that most wines score 5 or 6. A model that always guessed "6" would already have a fairly low MAE, so judge MAE against that, not on its own.

## Step 8: Compare the runs

### In the UI

Refresh `http://127.0.0.1:5000` and click the `wine-quality-regression` experiment. Tick all three runs and click **Compare**. You see the parameters and metrics side by side, and can plot `max_depth` against `mae`.

### From Python (src/compare.py)

```python
"""Print every run in the experiment, best MAE first."""
import mlflow

from src.config import EXPERIMENT_NAME, TRACKING_URI

mlflow.set_tracking_uri(TRACKING_URI)
runs = mlflow.search_runs(experiment_names=[EXPERIMENT_NAME], order_by=["metrics.mae ASC"])
cols = ["tags.mlflow.runName", "params.n_estimators", "params.max_depth",
        "metrics.mae", "metrics.rmse", "metrics.r2"]
print(runs[cols].round(4).to_string(index=False))
```

```bash
python -m src.compare
```

```text
   tags.mlflow.runName params.n_estimators params.max_depth  metrics.mae  metrics.rmse  metrics.r2
large-unbounded-forest                 300             None       0.4238        0.5536      0.5311
         medium-forest                 100                8       0.4586        0.5746      0.4949
  shallow-small-forest                  10                3       0.5349        0.6505      0.3524
```

`search_runs` reads the same store the UI reads, so the two must always agree. If a run appears in one but not the other, two different tracking URIs are in use somewhere.

## Step 9: Register the best model (src/register.py)

A run's model is a file tied to that one run. A **registered model** is a name with numbered versions (`wine-quality-regressor` v1, v2, ...). An **alias** such as `champion` is a label you move between versions. Deployment code loads `@champion` and never needs to know a run ID.

```python
"""Register the best run's model and point the 'champion' alias at it."""
import mlflow
from mlflow import MlflowClient

from src.config import EXPERIMENT_NAME, MODEL_NAME, TRACKING_URI

mlflow.set_tracking_uri(TRACKING_URI)
best = mlflow.search_runs(
    experiment_names=[EXPERIMENT_NAME], order_by=["metrics.mae ASC"], max_results=1
).iloc[0]

version = mlflow.register_model(f"runs:/{best.run_id}/model", MODEL_NAME)
MlflowClient().set_registered_model_alias(MODEL_NAME, "champion", version.version)
print(f"Registered {MODEL_NAME} version {version.version} "
      f"from run {best['tags.mlflow.runName']} (mae={best['metrics.mae']:.4f})")
print("Alias 'champion' -> version", version.version)
```

```bash
python -m src.register
```

```text
Registered wine-quality-regressor version 1 from run large-unbounded-forest (mae=0.4238)
Alias 'champion' -> version 1
```

In the UI, click **Models** at the top. `wine-quality-regressor` is listed with version 1 tagged `@champion`.

Running `register` again creates **version 2**; it never overwrites version 1. Keeping every version is what lets you roll back if a new model does worse in real use.

MLflow used to use stages (`Staging`, `Production`). Those are deprecated; aliases replace them.

## Step 10: Load the champion and predict (src/predict.py)

```python
"""Load the champion model from the registry and predict one wine."""
import mlflow
import mlflow.sklearn

from src.config import MODEL_NAME, TRACKING_URI
from src.data import load_split

mlflow.set_tracking_uri(TRACKING_URI)
model = mlflow.sklearn.load_model(f"models:/{MODEL_NAME}@champion")

_, X_test, _, y_test = load_split()
pred = model.predict(X_test.iloc[[0]])[0]
print(f"Predicted quality: {pred:.2f}  (actual: {y_test.iloc[0]})")
```

```bash
python -m src.predict
```

```text
Predicted quality: 5.36  (actual: 6)
```

Loading through `models:/wine-quality-regressor@champion` proves the registry works end to end. To ship a better model later, register it and move the alias. The loading code does not change.

**Always run scripts as modules: `python -m src.train`, never `python src/train.py`.** Run as a plain file, Python cannot find the `src` package and fails with `ModuleNotFoundError: No module named 'src'`.

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'src'` | Ran `python src/train.py` | Run `python -m src.train` from the project root |
| `ConnectionError ... 127.0.0.1:5000` | The MLflow server from Step 4 is not running | Start it in a second terminal and leave it open |
| `Address already in use` when starting the server | An old server is still on port 5000 | `lsof -i :5000` to find it, then stop it, or use `--port 5001` and update `config.py` |
| Runs missing from the UI | A script logged to a different place (e.g. a local `./mlruns` folder) | Check that `TRACKING_URI` in `config.py` matches the server address |
| `RESOURCE_DOES_NOT_EXIST` in `register` | The experiment has no runs yet, or the server was started from a different folder | Run Step 7 first; always start the server from the project folder |
| `Registered model alias champion not found` in `predict` | `register` has not been run | Run `python -m src.register` |
| `ValueError: invalid literal for int()` in `train` | Wrote `None` with a capital or a typo as the depth | Use a number or `none` |
