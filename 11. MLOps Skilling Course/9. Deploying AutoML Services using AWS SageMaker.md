# Deploying AutoML Services using AWS SageMaker

## Overview

You will hand a raw table of concrete mixes to **SageMaker Autopilot**, AWS's managed AutoML service. Autopilot picks the preprocessing, tries many algorithms and settings, and gives you a ranked leaderboard. You then deploy the best candidate to an endpoint and check it against data it has never seen, and against a model you built yourself in ten lines.

By the end, you will be able to:

- Keep a final test set aside **before** handing data to AutoML.
- Build a local baseline so you know whether AutoML adds anything.
- Launch an Autopilot job, follow its progress, and read its leaderboard.
- Deploy the best candidate and call it with CSV input.
- Delete the endpoint and its leftovers.

**Prerequisites:** Python 3.11. Steps 1–5 are free and run locally. **Steps 6–11 need an AWS account** with SageMaker and S3 access, a SageMaker execution role (the `AmazonSageMakerFullAccess` policy is enough), and the AWS CLI configured (`aws configure`). Autopilot training costs money, and the endpoint bills per hour; do Step 11 (clean up) the same day.

**Dataset:** [UCI Concrete Compressive Strength](https://archive.ics.uci.edu/dataset/165/concrete+compressive+strength), 1,030 lab-tested concrete mixes: 7 ingredient amounts plus curing age in days, and the measured strength in MPa. It is a **regression** problem (predict a number), unlike Sessions 4 and 8. Strength depends on age in a curved way (fast early gains, then levelling off), which is the kind of pattern AutoML's tree models find without hand-made features. It is downloaded automatically by the code.

**Compared with Session 4 (Vertex AI AutoML):** both take a table and return a deployable model. Autopilot also shows you the whole leaderboard of candidates, and deploys the winner on the same SageMaker endpoints you used in Session 8.

## Step 4: Prepare the data and keep a holdout (src/prepare\_data.py)

```python
"""Download the concrete data, rename the columns, and keep 10% aside as a final test."""
from sklearn.model_selection import train_test_split
from ucimlrepo import fetch_ucirepo

from src.config import FEATURES, TARGET

df = fetch_ucirepo(id=165).data.original
df.columns = FEATURES + [TARGET]          # short names without spaces
print(f"{len(df)} mixes, {df.isna().sum().sum()} missing values")
print(df.describe().T[["min", "max"]].round(1).to_string())

train, holdout = train_test_split(df, test_size=0.1, random_state=42)
train.to_csv("data/train.csv", index=False)
holdout.to_csv("data/holdout.csv", index=False)
print(f"\ntrain: {len(train)} rows -> data/train.csv (Autopilot sees only this)")
print(f"holdout: {len(holdout)} rows -> data/holdout.csv (final test, never uploaded)")
```

**Why a holdout, when Autopilot splits the data itself?** Autopilot picks its winner using its own validation split. A score used to *choose* the best of 20 candidates is optimistic: some of that win is luck on that particular split. The 103 holdout rows are never uploaded, so they give an honest score at the end and a fair comparison with the baseline.

## Step 5: Build a local baseline (src/baseline.py)

```python
"""Hand-built models, so we know what Autopilot has to beat."""
import pandas as pd
from sklearn.ensemble import RandomForestRegressor
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error

from src.config import FEATURES, TARGET

train = pd.read_csv("data/train.csv")
holdout = pd.read_csv("data/holdout.csv")

for name, model in [("linear regression", LinearRegression()),
                    ("random forest", RandomForestRegressor(n_estimators=300, random_state=42))]:
    model.fit(train[FEATURES], train[TARGET])
    rmse = mean_squared_error(holdout[TARGET], model.predict(holdout[FEATURES])) ** 0.5
    print(f"{name:<18} holdout RMSE = {rmse:.2f} MPa")
```

```bash
python -m src.baseline
```

```text
linear regression  holdout RMSE = 10.06 MPa
random forest      holdout RMSE = 5.28 MPa
```

**RMSE** (root mean squared error) is in the same unit as the target. "Off by about 5 MPa" is something an engineer can judge; MSE, in squared MPa, is not. The forest halves the linear model's error, which confirms the relationship is strongly non-linear. **Autopilot has to beat 5.28 MPa to be worth its cost.**

Everything up to here was free.

## Step 7: Launch Autopilot

### src/launch.py

```python
"""Start the Autopilot job and return immediately. It runs on AWS for 30-60 minutes."""
from sagemaker import AutoML

from src.config import BUCKET, JOB_NAME, PREFIX, ROLE_ARN, TARGET

automl = AutoML(
    role=ROLE_ARN,
    target_attribute_name=TARGET,
    output_path=f"s3://{BUCKET}/{PREFIX}/output",
    problem_type="Regression",
    job_objective={"MetricName": "MSE"},
    max_candidates=20,
)
automl.fit(inputs=f"s3://{BUCKET}/{PREFIX}/input/train.csv",
           job_name=JOB_NAME, wait=False)
print(f"started Autopilot job {JOB_NAME}")
print("check progress with: python -m src.status")
```

- **`problem_type="Regression"`** and **`job_objective` MSE**: we tell Autopilot what kind of problem this is and what to minimise, instead of letting it guess.
- **`max_candidates=20`** caps the search. More candidates cost more and take longer.
- **`wait=False`** returns straight away. The job runs on AWS for 30–60 minutes; your terminal does not need to stay open. The job name lets later scripts reattach to it.

### src/status.py

```python
"""Print where the Autopilot job is."""
import boto3

from src.config import JOB_NAME, REGION

job = boto3.client("sagemaker", region_name=REGION).describe_auto_ml_job(AutoMLJobName=JOB_NAME)
print(f"{JOB_NAME}: {job['AutoMLJobStatus']} / {job['AutoMLJobSecondaryStatus']}")
if job["AutoMLJobStatus"] == "Failed":
    print("reason:", job.get("FailureReason"))
```

```bash
python -m src.launch
python -m src.status        # run every few minutes
```

The second part of the status moves through these phases:

| Phase | What Autopilot is doing |
| --- | --- |
| `AnalyzingData` | Reading the CSV and choosing preprocessing per column (this replaces the scaler you wrote by hand in Session 8) |
| `FeatureEngineering` | Building the candidate preprocessing pipelines |
| `ModelTuning` | Training and scoring the 20 candidates |
| `Completed` | Done; the leaderboard is ready |

If the job stays in `AnalyzingData` for a long time or fails early, the cause is almost always the S3 path or the role's permission to read it. `status` prints the failure reason.

## Step 8: Read the leaderboard

### src/leaderboard.py

```python
"""Show the five best candidates Autopilot trained."""
from sagemaker import AutoML

from src.config import JOB_NAME

automl = AutoML.attach(auto_ml_job_name=JOB_NAME)
candidates = automl.list_candidates(sort_by="FinalObjectiveMetricValue",
                                    sort_order="Ascending")
for rank, c in enumerate(candidates[:5], start=1):
    mse = c["FinalAutoMLJobObjectiveMetric"]["Value"]
    print(f"{rank}. {c['CandidateName']:<55} MSE={mse:7.2f}  RMSE={mse ** 0.5:5.2f} MPa")
```

```bash
python -m src.leaderboard
```

You see five candidate names, best (lowest MSE) first, with their RMSE. Candidate names encode the algorithm, e.g. `xgboost` or `linear-learner`.

How to read it:

- **Are the top few close together?** If so, the search found a genuinely good region. If the winner is far ahead of number two, part of its win may be luck on Autopilot's own validation split.
- **Is a linear candidate much worse?** That matches the baseline in Step 5: the relationship is non-linear.
- **These are validation scores**, used to choose the winner. The honest score comes in Step 10.

## Step 9: Deploy the best candidate (src/deploy.py)

```python
"""Deploy Autopilot's best candidate to a real-time endpoint. Billing starts now."""
from sagemaker import AutoML

from src.config import ENDPOINT_NAME, JOB_NAME

automl = AutoML.attach(auto_ml_job_name=JOB_NAME)
best = automl.best_candidate()
print(f"deploying {best['CandidateName']}")
print(f"containers in its inference pipeline: {len(best['InferenceContainers'])}")

automl.deploy(initial_instance_count=1, instance_type="ml.m5.large",
              candidate=best, endpoint_name=ENDPOINT_NAME)
print(f"\nendpoint in service: {ENDPOINT_NAME}")
```

```bash
python -m src.deploy
```

The script prints how many containers the candidate needs, usually 2 or 3. An Autopilot model is an **inference pipeline**: a preprocessing container that repeats whatever Autopilot learned in `FeatureEngineering`, followed by the model container. Session 8 deployed one container you wrote yourself; here Autopilot wrote them all. Deployment takes about 10 minutes.

## Step 10: Score the endpoint on the holdout (src/evaluate.py)

```python
"""Score the endpoint on the 103 holdout mixes it has never seen."""
import boto3
import pandas as pd
from sklearn.metrics import mean_squared_error

from src.config import ENDPOINT_NAME, FEATURES, REGION, TARGET

holdout = pd.read_csv("data/holdout.csv")
# CSV has no column names, only positions. Always build it from FEATURES, in order.
body = holdout[FEATURES].to_csv(header=False, index=False)

runtime = boto3.client("sagemaker-runtime", region_name=REGION)
response = runtime.invoke_endpoint(EndpointName=ENDPOINT_NAME,
                                   ContentType="text/csv", Accept="text/csv", Body=body)
predictions = [float(line) for line in response["Body"].read().decode().splitlines()]

rmse = mean_squared_error(holdout[TARGET], predictions) ** 0.5
print(f"first mix: predicted {predictions[0]:.1f} MPa, actual {holdout[TARGET].iloc[0]:.1f} MPa")
print(f"Autopilot holdout RMSE = {rmse:.2f} MPa  ({len(predictions)} mixes)")
```

```bash
python -m src.evaluate
```

The request body is plain CSV, one mix per line, **no header**:

```text
266.0,114.0,0.0,228.0,0.0,932.0,670.0,365
362.6,189.0,0.0,164.9,11.6,944.7,755.8,7
...
```

and the endpoint answers with one number per line. Now compare like with like: the Autopilot RMSE and the baseline's **5.28 MPa** are both measured on the same 103 unseen mixes.

**The column order trap.** CSV has no field names, only positions. If you send the columns in another order (say, alphabetical), the endpoint still returns numbers, with no error, and they are wrong. A wrong but plausible number is the only symptom. That is why `evaluate.py` builds the CSV from `FEATURES`, the same list used to write the training file, instead of a hand-typed row. Session 7's Pydantic schema would catch this; a CSV endpoint cannot.

## Step 11: Clean up (do not skip)

### src/cleanup.py

```python
"""Delete the endpoint, its config and its models so nothing keeps billing."""
import boto3

from src.config import ENDPOINT_NAME, REGION

sm = boto3.client("sagemaker", region_name=REGION)
config_name = sm.describe_endpoint(EndpointName=ENDPOINT_NAME)["EndpointConfigName"]
model_names = [v["ModelName"] for v in
               sm.describe_endpoint_config(EndpointConfigName=config_name)["ProductionVariants"]]

sm.delete_endpoint(EndpointName=ENDPOINT_NAME)
sm.delete_endpoint_config(EndpointConfigName=config_name)
for name in model_names:
    sm.delete_model(ModelName=name)
print(f"deleted endpoint {ENDPOINT_NAME}, config {config_name}, models {model_names}")
```

```bash
python -m src.cleanup
```

Check **SageMaker → Inference → Endpoints** in the console: it must be empty.

Autopilot also left every candidate's files, notebooks and reports in S3 under `output/`. S3 storage costs little but bills forever. If you will not redeploy a candidate, remove them:

```bash
aws s3 rm s3://your-sagemaker-bucket/concrete-autopilot/ --recursive
```

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `NoCredentialsError` | AWS CLI not configured | `aws configure` |
| Job fails with a reason mentioning the target attribute | `TARGET` does not match the CSV header | Use the renamed columns from `prepare_data.py` and re-upload |
| Job fails early with an S3 `AccessDenied` | The SageMaker role cannot read the bucket | Attach `AmazonSageMakerFullAccess` or grant read on the bucket |
| `ResourceInUse` when launching | Job names are unique forever in your account | Change `JOB_NAME` in `config.py` |
| `leaderboard` shows nothing, or `deploy` errors | The job is still running | Wait until `status` shows `Completed` |
| `ValidationError ... Endpoint ... not found` | Endpoint not deployed yet, deleted, or wrong region | Run `deploy`; check `REGION` |
| Predictions are numbers but RMSE is huge | Columns sent in the wrong order, or a header row sent | Build the body from `FEATURES` with `header=False` |
| Unexpected bill | Endpoint still running, or files left in S3 | Run `cleanup`; delete the S3 output |
