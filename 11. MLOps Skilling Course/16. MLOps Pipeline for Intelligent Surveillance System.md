# MLOps Pipeline for Intelligent Surveillance System

## Overview

You will build an occupancy detector for a smart building: is someone in this room right now? It uses **ambient sensors only** (temperature, humidity, light, CO₂), with no camera. You train it on a time-based split, find out which sensor it cannot live without, build a fallback model, and write health checks that catch failing sensors **without** needing ground-truth labels. Then you run the same consumer on **Pub/Sub**.

Why no camera? It is a real design choice, not a toy limit:

- **Privacy.** A CO₂ reading cannot identify anyone. In offices, schools and hospitals this often decides whether a system can be deployed at all.
- **Cost.** Five numbers a minute instead of a video stream per room.
- **But:** a broken camera usually fails visibly (a black frame). A broken sensor usually keeps reporting **believable numbers that are wrong**, while every dashboard stays green. Most of this lab is about that.

```text
sensors ──► Pub/Sub ──► consumer: 60-reading window ──► health checks ──► main model
                                                              │              or fallback
                                                              └──► alerts: which sensor, since when
```

By the end, you will be able to:

- Split time-series data by time, and compute rolling features without crossing gaps.
- Use permutation importance to find a single point of sensor failure before deployment.
- Write label-free health checks, each with the window length that suits it.
- Fail over to a fallback model when a critical sensor dies.
- Publish readings to Pub/Sub and score them in windows with a consumer.

**Prerequisites:** Python 3.11. Steps 1–9 run locally. Step 10 (optional) needs a Google Cloud project; Pub/Sub at this scale costs a few cents.

**Dataset:** [UCI Occupancy Detection](https://archive.ics.uci.edu/dataset/357/occupancy+detection), 20,560 sensor readings, one per minute, from an office in February 2015, with the true occupancy taken from time-stamped photos. It is downloaded automatically by the code.

## Step 3: Load the data and build stream features (src/data.py)

```python
"""Load the UCI Occupancy Detection sensor log and build stream features."""
import pandas as pd

SENSORS = ["Temperature", "Humidity", "Light", "CO2", "HumidityRatio"]
TARGET = "Occupancy"


def load_occupancy():
    from ucimlrepo import fetch_ucirepo

    df = fetch_ucirepo(id=357).data.original
    # The three original files were stacked with their header rows still inside.
    df["date"] = pd.to_datetime(df["date"], errors="coerce")
    df = df.dropna(subset=["date"]).copy()
    df[SENSORS] = df[SENSORS].apply(pd.to_numeric)
    df[TARGET] = df[TARGET].astype(int)
    return df.drop(columns=["id"]).sort_values("date").reset_index(drop=True)


def make_features(frame):
    """Rolling features computed per continuous segment, never across a gap in the log."""
    X = frame.sort_values("date").copy()
    X["segment"] = (X["date"].diff() > pd.Timedelta(minutes=5)).cumsum()
    X["hour"] = X["date"].dt.hour
    X["is_workday"] = (X["date"].dt.weekday < 5).astype(int)
    by_segment = X.groupby("segment")
    for col in ["CO2", "Light", "Temperature"]:
        X[f"{col}_roll5"] = by_segment[col].transform(lambda s: s.rolling(5, min_periods=1).mean())
        X[f"{col}_delta5"] = X[col] - X[f"{col}_roll5"]
    X["CO2_slope15"] = by_segment["CO2"].transform(lambda s: s.diff(15)).fillna(0.0)
    return X


FEATURES = SENSORS + ["hour", "is_workday", "CO2_roll5", "CO2_delta5", "Light_roll5",
                      "Light_delta5", "Temperature_roll5", "Temperature_delta5", "CO2_slope15"]
NO_LIGHT = [f for f in FEATURES if not f.startswith("Light")]
```

What each part does:

- **The raw data has two stray header rows.** UCI joined three files, and their header lines (`date, Temperature, ...`) ended up as data rows, turning every column into text. `errors="coerce"` turns those rows' dates into `NaT`, and we drop them.
- **Stream features.** One reading tells you little; **change** tells you more. CO₂ *rising* means someone just walked in; CO₂ *high but flat* can be an empty room after a meeting. `roll5` is the 5-minute average, `delta5` the jump from it, `CO2_slope15` the change over 15 minutes.
- **Segments.** The log has two gaps (7 and 29 hours) where the files meet. A rolling window across a gap would mix readings a day apart. A new segment starts after any gap longer than 5 minutes, and rolling features restart there.
- **`NO_LIGHT`** is the feature list for a fallback model that never looks at the light sensor (Step 5 explains why).

## Step 4: Train on a time-based split (src/train.py)

```python
"""Train the main model and a light-free fallback on a time-based split."""
import json

import joblib
import pandas as pd
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import confusion_matrix

from src.data import FEATURES, NO_LIGHT, SENSORS, TARGET, load_occupancy, make_features

df = make_features(load_occupancy())
print(f"{len(df)} readings, {df.date.min()} to {df.date.max()}, "
      f"{df['segment'].nunique()} continuous segments")
print(f"occupied {df[TARGET].mean():.3f} of the time")

cut = df["date"].quantile(0.70)                 # first 70% of the timeline trains
train, test = df[df["date"] <= cut], df[df["date"] > cut]
print(f"train {len(train)} rows to {train.date.max()}, test {len(test)} rows from {test.date.min()}")
print(f"CO2 change over 15 min: occupied {df.loc[df[TARGET] == 1, 'CO2_slope15'].mean():+.1f} ppm, "
      f"empty {df.loc[df[TARGET] == 0, 'CO2_slope15'].mean():+.1f} ppm\n")

models = {}
for name, cols in [("main", FEATURES), ("no_light", NO_LIGHT)]:
    clf = HistGradientBoostingClassifier(max_iter=300, learning_rate=0.08,
                                         max_depth=6, random_state=42)
    clf.fit(train[cols], train[TARGET])
    pred = clf.predict(test[cols])
    tn, fp, fn, tp = confusion_matrix(test[TARGET], pred).ravel()
    print(f"{name:<9} accuracy {(pred == test[TARGET]).mean():.4f}   "
          f"TN {tn}  FP {fp}  FN {fn}  TP {tp}")
    models[name] = {"model": clf, "features": cols}
print(f"always 'empty' accuracy {1 - test[TARGET].mean():.4f}")

daily_co2_floor = train.groupby(train["date"].dt.date)["CO2"].min()
baseline = {
    "occupancy_rate": float(train[TARGET].mean()),
    "co2_daily_floor_max": float(daily_co2_floor.max()),
    "sensors": {c: {"p01": float(train[c].quantile(0.01)), "p99": float(train[c].quantile(0.99)),
                    "mean": float(train[c].mean()), "std": float(train[c].std())}
                for c in SENSORS},
}
joblib.dump(models, "model/occupancy.joblib")
train[SENSORS].to_csv("model/reference.csv", index=False)
test.to_csv("model/test_stream.csv", index=False)
with open("model/baseline.json", "w") as f:
    json.dump(baseline, f, indent=2)
print("CO2 normal range (p01-p99):",
      round(baseline["sensors"]["CO2"]["p01"]), "-", round(baseline["sensors"]["CO2"]["p99"]))
print(f"highest daily CO2 minimum in training: {baseline['co2_daily_floor_max']:.0f} ppm")
```

- **Split by time, never at random.** Readings are one minute apart. A random split would train on 09:41 and test on 09:42, which is nearly testing on the training data. Here the model trains on the first 70% of the timeline and is tested on the last 30%.
- **CO₂ slope separates the classes** by physics: people breathe out CO₂ faster than the room ventilates it (+16 ppm per 15 min when occupied, −4 when empty).
- **The main model is 99.6% accurate**, an easy physical problem, not leakage. The **light-free fallback** is far worse (87.6%, with 723 false alarms), but still better than always answering "empty" (82.2%).
- **The baseline** stores each sensor's normal range (1st to 99th percentile) and the **highest daily CO₂ minimum** seen in training. Both are used by the health checks.

## Step 5: Find the single point of failure (src/importance.py)

Before deploying a sensor model, ask: **which sensor would it not survive losing?**


## Step 6: Label-free health checks (src/health.py)

In production there are no labels: nobody tells you whether the room was really occupied. The checks must work from the sensor readings alone.

```python
"""Label-free sensor health checks. Each one looks at the window length that suits it."""
STUCK_HOURS = 4            # a live light sensor always changes within 4 daytime hours
FLOOR_MARGIN = 50          # ppm above the highest daily CO2 minimum seen in training


def out_of_range(window, baseline, max_share=0.05):
    """Fast check on the last 60 readings: values outside what training ever saw."""
    bad = []
    for col, b in baseline["sensors"].items():
        share = ((window[col] < b["p01"]) | (window[col] > b["p99"])).mean()
        if share > max_share:
            bad.append(col)
    return bad


def light_stuck(history):
    """Light is flat over the last 4 hours, judged only in daytime (lights off at night is normal)."""
    recent = history.tail(STUCK_HOURS * 60)
    daytime = recent["date"].dt.hour.between(9, 17).all()
    return bool(daytime and recent["Light"].std() < 1e-6)


def co2_floor_shift(history, baseline):
    """An empty room drifts back towards outdoor air (~420 ppm) every night.
    If the lowest reading of the last 24 hours is far above that, the sensor has shifted."""
    floor = history.tail(24 * 60)["CO2"].min()
    return floor > baseline["co2_daily_floor_max"] + FLOOR_MARGIN, floor
```

| Check | Window | Catches | Why this window |
| --- | --- | --- | --- |
| `out_of_range` | last 60 readings | Values the sensor never produced in training | Cheap, fast, needs no history |
| `light_stuck` | last 4 hours, daytime only | A dead sensor reporting a constant | At night, Light = 0 for hours is **normal**; a stuck check run at night would fire every evening |
| `co2_floor_shift` | last 24 hours | A CO₂ sensor drifting upward | An empty room airs out towards ~420 ppm at least once a day; a sensor whose daily minimum stays high has shifted |

**Why not a statistical drift test on each window?** A first version of this lab compared every 60-minute window with the whole training set using a KS test. It fired on **every** window, including normal ones: one hour of readings always looks different from nine days of readings (an hour at night versus all hours). Each check needs a window long enough to contain "normal" variation.

**A range check asks whether a value is possible; a variance check asks whether the sensor is alive.** A sensor stuck at 0 lux passes the range check, because 0 lux is a perfectly possible reading in a dark room.

### tests/test\_health.py

```python
import pandas as pd

from src.health import co2_floor_shift, light_stuck, out_of_range

BASELINE = {
    "co2_daily_floor_max": 500.0,
    "sensors": {"CO2": {"p01": 420.0, "p99": 1800.0}, "Light": {"p01": 0.0, "p99": 1500.0}},
}


def readings(hours, start="2015-02-16 09:00", light=300.0, co2=600.0):
    dates = pd.date_range(start, periods=hours * 60, freq="1min")
    return pd.DataFrame({"date": dates, "Light": light, "CO2": co2})


def test_constant_light_in_daytime_is_stuck():
    assert light_stuck(readings(4, light=0.0))


def test_dark_at_night_is_not_stuck():
    assert not light_stuck(readings(4, start="2015-02-16 00:00", light=0.0))

    shifted, floor = co2_floor_shift(readings(24, co2=700.0), BASELINE)

    day = readings(24, co2=600.0)
    day.loc[100:200, "CO2"] = 430.0          # the room aired out overnight
    assert not co2_floor_shift(day, BASELINE)[0]
```

## Step 7: Simulate the streaming consumer (src/stream.py)

This script replays the 4.3-day test period as a stream, one 60-reading window at a time, exactly as a consumer would see it. It runs the health checks, chooses the main or fallback model, and records when each alert first fired. With `light_stuck`, the light sensor dies one day in.

```python
"""Simulate the streaming consumer: score each 60-reading window, run health checks, fail over.

Usage: python -m src.stream as_recorded | light_stuck
"""
import json
import sys

import joblib
import numpy as np
import pandas as pd

from src.data import FEATURES, TARGET, make_features
from src.health import co2_floor_shift, light_stuck, out_of_range

scenario = sys.argv[1]
models = joblib.load("model/occupancy.joblib")
baseline = json.load(open("model/baseline.json"))
stream = pd.read_csv("model/test_stream.csv", parse_dates=["date"])
raw = stream.drop(columns=[c for c in FEATURES if c not in baseline["sensors"]] + ["segment"])

FAULT_AT = 1440                                   # the fault starts one day into the stream
if scenario == "light_stuck":
    raw.loc[raw.index[FAULT_AT:], "Light"] = 0.0
stream = make_features(raw).reset_index(drop=True)

alerts, rows = {}, []
light_fault = False                               # stays on until a technician resets it
for start in range(60, len(stream) + 1, 60):
    history, window = stream.iloc[:start], stream.iloc[start - 60:start]
    when = window["date"].iloc[-1]

    found = {f"{c} out of range" for c in out_of_range(window, baseline)}
    if light_stuck(history):
        found.add("Light stuck")
        light_fault = True
    shifted, floor = co2_floor_shift(history, baseline)
    if shifted:
        found.add("CO2 floor shifted")
    for name in found:
        alerts.setdefault(name, when)                 # remember the first time each alert fired

    use_fallback = light_fault or "Light out of range" in found
    chosen = models["no_light" if use_fallback else "main"]
    pred = chosen["model"].predict(window[chosen["features"]])
    no_failover = models["main"]["model"].predict(window[models["main"]["features"]])
    rows.append({"start": start, "fallback": use_fallback, "pred": pred.mean(),
                 "correct": (pred == window[TARGET]).sum(),
                 "correct_no_failover": (no_failover == window[TARGET]).sum(), "n": len(window)})

log = pd.DataFrame(rows)
after = log[log.start > FAULT_AT]
print(f"scenario: {scenario}   {stream.date.min():%a %d %b %H:%M} -> {stream.date.max():%a %d %b %H:%M}")
print("first time each alert fired:")
for name, when in sorted(alerts.items(), key=lambda kv: kv[1]):
    print(f"  {when:%a %d %b %H:%M}  {name}")
if not alerts:
    print("  none")
print(f"windows on the fallback model: {log.fallback.sum()} of {len(log)}")
print(f"accuracy after day 1 with failover   : {after.correct.sum() / after.n.sum():.4f}")
print(f"accuracy after day 1 without failover: {after.correct_no_failover.sum() / after.n.sum():.4f}")
print(f"predicted occupancy after day 1: {np.average(after.pred, weights=after.n):.3f}")
```

- **Features are recomputed from the faulty raw readings**, exactly as a real consumer would; a dead sensor also corrupts every rolling feature built on it.
- **`light_fault` latches.** The stuck check only runs in daytime, so without latching the consumer would switch back to the main model every evening. Once a sensor is declared dead, it stays dead until someone fixes it and resets the flag.
- **Accuracy is printed only because this replay has labels.** A live system cannot compute it; that is why the health checks exist.

**Every mechanism that makes a pipeline tolerant of bad input also makes it silent about bad input.** A sensor pipeline needs a range check per sensor, a liveness check per sensor, and a degraded mode for every sensor the importance analysis marks as critical.

## Step 10 (optional): Run the consumer on Pub/Sub

**Pub/Sub** is Google Cloud's message queue: sensors publish readings to a **topic**; consumers pull them from a **subscription**.

```bash
gcloud auth login
```

The **ack deadline** is the consumer's time budget: a message not acknowledged within 60 seconds is delivered again, so the same readings would be scored twice. Scoring a window takes milliseconds, so there is plenty of room.

### src/consume.py

```python
"""Pull readings from Pub/Sub in 60-reading windows, check health, score, acknowledge.

Usage: python -m src.consume <project-id>
"""
import json
import sys
import time

import joblib
import pandas as pd
from google.api_core.exceptions import DeadlineExceeded
from google.cloud import pubsub_v1

from src.data import make_features
from src.health import out_of_range

project = sys.argv[1]
models = joblib.load("model/occupancy.joblib")
baseline = json.load(open("model/baseline.json"))
subscriber = pubsub_v1.SubscriberClient()
subscription = subscriber.subscription_path(project, "room-sensors-scorer")

buffer, ack_ids = [], []
history = pd.DataFrame()          # the last 15 readings, so rolling features see the past
while True:
    try:
        resp = subscriber.pull(request={"subscription": subscription, "max_messages": 60},
                               timeout=30)
    except DeadlineExceeded:
        resp = None
    if not resp or not resp.received_messages:
        print("no more messages")
        break
    for msg in resp.received_messages:
        buffer.append(json.loads(msg.message.data))
        ack_ids.append(msg.ack_id)
    if len(buffer) >= 60:
        t0 = time.perf_counter()
        new = pd.DataFrame(buffer).assign(date=lambda d: pd.to_datetime(d["date"]))
        window = make_features(pd.concat([history, new])).tail(len(new))
        history = new.sort_values("date").tail(15)
        bad = out_of_range(window, baseline)
        chosen = models["no_light" if "Light" in bad else "main"]
        occupied = chosen["model"].predict(window[chosen["features"]]).mean()
        subscriber.acknowledge(request={"subscription": subscription, "ack_ids": ack_ids})
        print(f"{window.date.iloc[-1]}  occupied {occupied:.2f}  alerts {bad or '-'}  "
              f"{(time.perf_counter() - t0) * 1000:.0f} ms")
        buffer, ack_ids = [], []
```

- **`history` keeps the last 15 readings.** `CO2_slope15` needs 15 minutes of past data. Computing features on each 60-reading window alone would give the first readings of every window different values from training: a **training/serving skew** with no error message. With the history, the consumer's features match the training features exactly.
- **Messages are acknowledged only after scoring.** If the consumer crashes mid-window, Pub/Sub redelivers the readings instead of losing them.
- **`make_features` sorts by date.** Pub/Sub does not guarantee message order.

```bash
python -m src.publish your-gcp-project-id 600
python -m src.consume your-gcp-project-id
```

The consumer prints one line per window: time, share of occupied minutes, alerts and scoring time in milliseconds. Clean up the subscription first, then the topic:

```bash
gcloud pubsub subscriptions delete room-sensors-scorer --quiet
gcloud pubsub topics delete room-sensors --quiet
```

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `ValueError: time data "Temperature" doesn't match format` | Stray header rows inside the UCI data | `pd.to_datetime(..., errors="coerce")` and drop `NaT` rows, as in `load_occupancy` |
| Test accuracy suspiciously high with a random split | Neighbouring minutes in train and test | Split by time |
| Rolling features jump at file boundaries | Rolling across a gap in the log | Compute per segment (`groupby("segment")`) |
| Health checks fire on every window | Statistical test on a too-short window | Give each check a window that contains normal variation |
| "Light stuck" fires every night | Stuck check run in the dark | Judge light only in daytime hours |
| Consumer predictions differ from `stream.py` | Rolling features computed per window without history | Keep the last 15 readings (`history`) |
| `NotFound: ... subscriptions/room-sensors-scorer` | Subscription not created | Run the `gcloud pubsub` commands in Step 10 |
| Same readings scored twice | Not acknowledged within the ack deadline | Acknowledge after each window; raise `--ack-deadline` if needed |
