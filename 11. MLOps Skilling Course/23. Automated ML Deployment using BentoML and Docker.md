# Automated ML Deployment using BentoML and Docker

## Overview

In Sessions 6 and 7 you wrote the whole serving layer by hand: the FastAPI app, the request models, the model loading, `requirements.txt`, the Dockerfile. In this session **BentoML** generates most of it. You save a model into BentoML's versioned **model store**, write one small service class, build a **Bento** (model + code + dependencies in one versioned package), and let BentoML generate the Docker image.

| | Session 6 (by hand) | This session (BentoML) |
| --- | --- | --- |
| Serving app | FastAPI routes + Pydantic models | One `@bentoml.api` method with type hints |
| Model loading | `joblib.load` from a file path | From the model store, by version tag |
| Dependencies | Your `requirements.txt` | Declared in `bentofile.yaml` |
| Dockerfile | Written and maintained by you | Generated by `bentoml containerize` |
| Versioning | Image tag only | Model tag **and** Bento tag, both immutable |
| API docs | Generated by FastAPI | Generated by BentoML |

The trade is the usual one: less to maintain, less direct control. When you need something BentoML does not express, you fall back to Session 6.

By the end, you will be able to:

- Save a model into the BentoML model store with metadata and the objects it needs at serving time.
- Write a BentoML service with a typed, validated endpoint.
- Serve and test it locally, then build a Bento and a Docker image.
- Pin the exact model version a release serves.

**Prerequisites:** Python 3.11 and Session 6. Steps 1–7 run without Docker. Step 8 needs [Docker Desktop](https://www.docker.com/products/docker-desktop/) running.

**Dataset:** [UCI Glass Identification](https://archive.ics.uci.edu/dataset/42/glass+identification), 214 glass fragments from forensic casework, described by refractive index and the weight-percent of eight oxides (Na, Mg, Al, Si, K, Ca, Ba, Fe), labelled with one of six glass types (building windows of two kinds, vehicle windows, containers, tableware, headlamps). Training takes under a second, so the lab's time goes on packaging. It is downloaded automatically by the code.

## Step 3: Train and save into the model store (src/train.py)

```python
"""Train the glass classifier and save it into BentoML's model store."""
import bentoml
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score, f1_score
from sklearn.model_selection import train_test_split
from ucimlrepo import fetch_ucirepo

FEATURES = ["RI", "Na", "Mg", "Al", "Si", "K", "Ca", "Ba", "Fe"]

ds = fetch_ucirepo(id=42)
X, y = ds.data.features[FEATURES], ds.data.targets["Type_of_glass"]
print(f"{len(X)} glass fragments; class counts {y.value_counts().sort_index().to_dict()}")

X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, random_state=42, stratify=y)
clf = RandomForestClassifier(n_estimators=300, random_state=42).fit(X_tr, y_tr)
pred = clf.predict(X_te)
acc, f1 = accuracy_score(y_te, pred), f1_score(y_te, pred, average="macro")
print(f"accuracy {acc:.3f}   macro F1 {f1:.3f}   classes {clf.classes_.tolist()}")

saved = bentoml.sklearn.save_model(
    "glass_clf",
    clf,
    signatures={"predict_proba": {"batchable": True, "batch_dim": 0}},
    metadata={"dataset": "uci-glass-42", "accuracy": round(acc, 4), "macro_f1": round(f1, 4)},
    custom_objects={"features": FEATURES, "classes": clf.classes_.tolist()},
)
print(f"saved {saved.tag}")
```

```bash
python -m src.train
bentoml models list
```

```text
214 glass fragments; class counts {1: 70, 2: 76, 3: 17, 5: 13, 6: 9, 7: 29}
accuracy 0.833   macro F1 0.797   classes [1, 2, 3, 5, 6, 7]
saved glass_clf:qneobwwbrs3ak6r2

 Tag                         Module           Size      Creation Time
 glass_clf:qneobwwbrs3ak6r2  bentoml.sklearn  2.24 MiB  2026-10-06 19:17:46
```

(Your tag suffix will differ.) What each part does:

- **`save_model` is not `joblib.dump`.** It stores the model under a name and a **new, immutable version tag** each time (`glass_clf:qneobwwbrs3ak6r2`). Saving again adds a version and moves the `latest` alias; it never overwrites.
- **`custom_objects`** stores the feature order and class list **with** the model, so the service never hard-codes them and cannot drift out of sync.
- **`metadata`** records scores you can read later with `bentoml models get glass_clf:latest`.
- **`batchable=True`** lets BentoML combine concurrent requests into one `predict_proba` call (the batching win from Session 21).
- **The class labels are 1, 2, 3, 5, 6, 7.** There is no type 4 in the data. The service returns these labels exactly, read from `clf.classes_`.

## Step 4: The service (service.py)

```python
"""BentoML service: one typed method becomes a validated, documented HTTP endpoint."""
import os

import bentoml
import numpy as np
import pandas as pd
from bentoml.models import BentoModel
from pydantic import BaseModel


class Fragment(BaseModel):
    RI: float      # refractive index
    Na: float      # the rest are weight-percent of each oxide
    Mg: float
    Al: float
    Si: float
    K: float
    Ca: float
    Ba: float
    Fe: float


@bentoml.service(name="glass_classifier", resources={"cpu": "1"}, traffic={"timeout": 10})
class GlassClassifier:
    # Pin an exact version for releases: GLASS_MODEL=glass_clf:<tag> bentoml build
    model_ref = BentoModel(os.environ.get("GLASS_MODEL", "glass_clf:latest"))

    def __init__(self) -> None:
        # Inside the running service, model_ref is the resolved model from the store.
        self.model = bentoml.sklearn.load_model(self.model_ref)
        self.features = self.model_ref.custom_objects["features"]
        self.classes = self.model_ref.custom_objects["classes"]

    @bentoml.api
    def classify(self, fragment: Fragment) -> dict:
        row = pd.DataFrame([fragment.model_dump()])[self.features]   # training column order
        proba = self.model.predict_proba(row)[0]
        best = int(np.argmax(proba))
        return {
            "predicted_type": int(self.classes[best]),
            "confidence": round(float(proba[best]), 4),
            "scores": {str(c): round(float(p), 4) for c, p in zip(self.classes, proba)},
            "model_version": str(self.model_ref.tag),
        }
```

Notice what is **not** here: no web server start-up, no route paths, no JSON parsing, no file loading.

- **`@bentoml.service`** supplies the HTTP server; **`@bentoml.api`** turns the typed method into a `POST /classify` endpoint with input validation and API docs.
- **`model_ref = BentoModel(...)`** declares which model the service needs. BentoML resolves it from the store and, at build time, packs that exact version into the Bento.
- **The `Fragment` model** makes validation explicit: a missing or non-numeric field is rejected before your code runs.
- **A `DataFrame` in training column order**, so scikit-learn gets the feature names it was trained with.
- **`model_version` in every response**: when someone reports a strange answer, you know which model produced it.

## Step 5: Serve locally first

Always run the service outside a container first: a bug found here costs seconds, after an image build it costs minutes.

```bash
bentoml serve service:GlassClassifier --port 3000
```

```text
[INFO] [cli] Starting production HTTP BentoServer from "service:GlassClassifier" listening on http://localhost:3000
[INFO] [entry_service:glass_classifier:1] Service glass_classifier initialized
```

Reaching "initialized" means the model was found in the store. Open `http://localhost:3000` for the generated API page.

In a second terminal (with `BENTOML_HOME` set):

```bash
curl -s -X POST localhost:3000/classify -H "Content-Type: application/json" \
  -d '{"fragment": {"RI": 1.52101, "Na": 13.64, "Mg": 4.49, "Al": 1.1, "Si": 71.78, "K": 0.06, "Ca": 8.75, "Ba": 0.0, "Fe": 0.0}}'
```

```json
{"predicted_type": 1, "confidence": 0.8233, "scores": {"1": 0.8233, "2": 0.1167, "3": 0.05, "5": 0.0, "6": 0.0067, "7": 0.0033}, "model_version": "glass_clf:qneobwwbrs3ak6r2"}
```

This is the first type-1 fragment in the dataset (a float-processed building window), and the model is confident.

**The body is `{"fragment": {...}}`**, keyed by the method's **parameter name**. A flat body is rejected:

```bash
curl -s -X POST localhost:3000/classify -H "Content-Type: application/json" -d '{"RI": 1.52}'
```

```json
{"error":"1 validation error for Input","detail":[{"type":"missing","loc":["fragment"],"msg":"Field required", ...}]}
```

(HTTP status 400.) Text in a number field gets the same kind of response, naming each bad field: `"loc":["fragment","RI"],"msg":"Input should be a valid number"`.

A headlamp fragment (the first type-7 row in the data):

```bash
curl -s -X POST localhost:3000/classify -H "Content-Type: application/json" \
  -d '{"fragment": {"RI": 1.51131, "Na": 13.69, "Mg": 3.2, "Al": 1.81, "Si": 72.81, "K": 1.76, "Ca": 5.43, "Ba": 1.19, "Fe": 0.0}}'
```

```json
{"predicted_type": 7, "confidence": 0.36, "scores": {"1": 0.09, "2": 0.3467, "3": 0.0267, "5": 0.1733, "6": 0.0033, "7": 0.36}, ...}
```

Correct, but only 36% confident, with type 2 close behind. With 214 samples and 6 classes, the rare types are learned from very few examples. Returning all the scores lets a caller see that.

Stop the server with `Ctrl+C`.

## Step 6: Declare the Bento (bentofile.yaml)

A **Bento** is the deployable unit: service code + the model from the store + dependencies + Python version, in one versioned folder.

```yaml
service: "service:GlassClassifier"
labels:
  owner: mlops-course
include:
  - "service.py"
python:
  packages:
    - scikit-learn==1.5.2
    - numpy==2.1.1
    - pandas==2.2.3
docker:
  python_version: "3.11"
```

- **`include`** keeps the Bento small. Without it, BentoML packs the whole folder: venv, data and all.
- **You do not list the model.** BentoML finds it through `model_ref` in `service.py`.
- **The package pins are the riskiest lines.** They must match the versions that **trained** the model. A different scikit-learn inside the image may refuse to load the model, or load it and give slightly different answers. Check with `pip show scikit-learn`.

## Step 7: Build the Bento, pinning the model version

```bash
bentoml models list            # copy the tag you want to release
GLASS_MODEL=glass_clf:qneobwwbrs3ak6r2 bentoml build
bentoml get glass_classifier:latest
```

```text
Successfully built Bento(tag="glass_classifier:eeekh6wbrwmxg6r2").
...
services:
- name: glass_classifier
  models:
  - tag: glass_clf:qneobwwbrs3ak6r2
```

The Bento tag (`glass_classifier:...`) is a different identifier from the model tag; one Bento version wraps one model version. Check that the `models:` entry is exactly the model you meant to ship.

**Why pin with `GLASS_MODEL` instead of relying on `latest`?** In testing this lab, we retrained (a new model tag), then served the **previously built** Bento locally with `bentoml serve glass_classifier:latest`. The responses came from the **new** model: `model_version` showed the new tag, although the Bento's manifest listed the old one. When run on your machine, the service resolves `glass_clf:latest` against your local model store, and `latest` had moved. Inside the Docker image only the packed model exists, so it would serve the packed version, which means local tests and the container could quietly disagree. Setting `GLASS_MODEL` to an exact tag at build and serve time removes the ambiguity:

```bash
GLASS_MODEL=glass_clf:qneobwwbrs3ak6r2 bentoml serve glass_classifier:latest --port 3001
# every response now says "model_version": "glass_clf:qneobwwbrs3ak6r2"
```

## Step 8: Containerize and run (needs Docker)

`bentoml containerize` generates a Dockerfile from the Bento and runs `docker build`. You never write or maintain the Dockerfile.

```bash
docker version                     # must show both Client and Server
bentoml containerize glass_classifier:latest -t glass-classifier:0.1.0
docker run -d --rm -p 3000:3000 --name glass-svc glass-classifier:0.1.0
sleep 10 && docker logs glass-svc | tail -n 3
```

The log should show the server listening on `0.0.0.0:3000` (all interfaces, which is what makes the `-p` port mapping work) and `Service glass_classifier initialized`. Call it with the same `curl` as Step 5.

**The response must be identical to the local one**, the same `predicted_type`, `confidence` to four decimals, and `model_version`. That, not "the container started", is the success criterion: it proves packaging preserved the model and its numerical behaviour. Any difference in the scores means the image has different library versions from your laptop; fix the pins in `bentofile.yaml` and treat the deployment as failed even though every command reported success.

```bash
docker stop glass-svc
```

The image remains: it is an ordinary container image you can push to a registry and run on Kubernetes with Session 6's manifests.

### When containerizing fails

| Message | Cause | Fix |
| --- | --- | --- |
| `Cannot connect to the Docker daemon` | Docker is not running | Start Docker Desktop; the Bento is already built |
| `exec format error` when the image runs on a cloud host | Built on Apple Silicon (ARM) for an Intel/AMD host | `bentoml containerize glass_classifier:latest -t glass-classifier:0.1.0 --opt platform=linux/amd64` |
| `no space left on device` | Old images filling the disk | `docker system prune -f`, then retry |

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `NotFound: Model 'glass_clf:latest' is not found` | Model saved under a different `BENTOML_HOME` (or not saved) | Set the same `BENTOML_HOME` in every terminal; run `src.train` |
| `AttributeError: 'Model' object has no attribute 'stored'` | Treating `model_ref` as the `BentoModel` wrapper inside `__init__` | Inside the service, `self.model_ref` is already the resolved model; use it directly |
| `400 ... "loc":["fragment"] ... Field required` | Flat JSON body | Wrap the fields: `{"fragment": {...}}` |
| `UserWarning: X does not have valid feature names` | Passing a plain array to a model trained on a DataFrame | Build a `DataFrame` with `self.features` columns |
| The Bento is hundreds of MB | `include` missing, so the whole folder was packed | List only `service.py` under `include` |
| Responses show an unexpected `model_version` | `latest` resolved to another model | Build and serve with `GLASS_MODEL=glass_clf:<tag>` |
| Container scores differ from local | Different library versions in the image | Match the pins in `bentofile.yaml` to the training environment |
