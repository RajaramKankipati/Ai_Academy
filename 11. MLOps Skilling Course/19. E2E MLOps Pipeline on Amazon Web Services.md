# E2E MLOps Pipeline on Amazon Web Services

## Overview

Sessions 8 and 9 each did one piece of an AWS deployment by hand, in an order you had to remember. In this session you put every piece into one **SageMaker Pipeline**: preprocess the data, train, evaluate on a held-out test set, pass a quality gate, register the model as a **version** in the **SageMaker Model Registry**, and deploy only an **approved** version. One command reruns the whole journey from raw CSV to a live endpoint.

```text
S3 raw CSV ─► PreprocessCarData ─► TrainCarClassifier ─► EvaluateCarClassifier ─► MacroF1Gate
                                                                                   │        │
                                                     macro F1 ≥ 0.85 ◄─────────────┘        └─► MacroF1TooLow (fail)
                                                            │
                                         RegisterCarClassifier (PendingManualApproval)
                                                            │  a person approves
                                                            ▼
                                                   deploy ─► endpoint
```

Why a pipeline instead of scripts run in order:

- **Reproducible**: the pipeline definition is JSON stored in SageMaker, and the code that builds it lives in Git.
- **Lineage**: every execution records which input produced which model, automatically.
- **Gated**: a model below the quality bar never reaches the registry, and nothing reaches an endpoint without approval.

By the end, you will be able to:

- Write processing and evaluation scripts that follow SageMaker's folder contract, and rehearse them locally.
- Define processing, training, evaluation, condition, fail and register steps with the SageMaker Python SDK.
- Run, follow and debug a pipeline execution.
- Approve a model version in the registry and deploy it.

**Prerequisites:** Python 3.11 and Sessions 8 and 9. Steps 1–5 are free and run locally. **Steps 6–11 need an AWS account** with SageMaker, an S3 bucket, a SageMaker execution role (`AmazonSageMakerFullAccess` plus read/write on the bucket) and the AWS CLI configured (`aws configure`). An execution costs a few dollars; the endpoint bills per hour. Do Step 11 (clean up) the same day.

**Dataset:** [UCI Car Evaluation](https://archive.ics.uci.edu/dataset/19/car+evaluation), 1,728 cars described by six text attributes (`buying` price, `maint` cost, `doors`, `persons`, `lug_boot` size, `safety`) and rated `unacc`, `acc`, `good` or `vgood`. Every column is text, so preprocessing has real work to do. The classes are very unbalanced (70% `unacc`, under 4% each `good` and `vgood`), so the quality gate must look beyond accuracy. It is downloaded automatically by the code.

## Step 3: The processing script (pipeline/preprocessing.py)

A SageMaker processing job copies its S3 inputs to folders under `/opt/ml/processing/`, runs your script, then copies anything written to the output folders back to S3. **Those folders are the whole contract.** Reading the base folder from an environment variable lets the same script run locally.

```python
"""Encode the car data and split it. Runs as the pipeline's processing step."""
import os

import pandas as pd
from sklearn.model_selection import train_test_split

BASE = os.environ.get("PROCESSING_DIR", "/opt/ml/processing")   # SageMaker's fixed folders

# Every column has a natural order, so integer codes carry real information.
ORDINAL_MAPS = {
    "buying":   {"low": 0, "med": 1, "high": 2, "vhigh": 3},
    "maint":    {"low": 0, "med": 1, "high": 2, "vhigh": 3},
    "doors":    {"2": 2, "3": 3, "4": 4, "5more": 5},
    "persons":  {"2": 2, "4": 4, "more": 6},
    "lug_boot": {"small": 0, "med": 1, "big": 2},
    "safety":   {"low": 0, "med": 1, "high": 2},
}
LABEL_MAP = {"unacc": 0, "acc": 1, "good": 2, "vgood": 3}

df = pd.read_csv(f"{BASE}/input/car_evaluation.csv", dtype=str)
for col, mapping in ORDINAL_MAPS.items():
    df[col] = df[col].map(mapping)
df["class"] = df["class"].map(LABEL_MAP)
assert df.notna().all().all(), "unmapped category found -- check ORDINAL_MAPS"

# The built-in XGBoost container wants the label in the FIRST column and no header.
df = df[["class"] + list(ORDINAL_MAPS)]

train, rest = train_test_split(df, test_size=0.3, random_state=42, stratify=df["class"])
val, test = train_test_split(rest, test_size=0.5, random_state=42, stratify=rest["class"])
for name, part in [("train", train), ("validation", val), ("test", test)]:
    os.makedirs(f"{BASE}/output/{name}", exist_ok=True)
    part.to_csv(f"{BASE}/output/{name}/{name}.csv", index=False, header=False)
    print(f"{name}: {len(part)} rows")
```

Two lines guard against failures that would otherwise give no error at all:

- **`doors` and `persons` look like numbers but are text** (`"5more"`, `"more"`). `pd.to_numeric` would quietly turn about a quarter of the rows into missing values. The explicit maps, and the **`assert`**, turn any unexpected value into a loud failure at the first step.
- **Label first, no header.** The built-in XGBoost container treats the **first column** as the label. Put `buying` first by mistake and it trains happily on the wrong target, producing a model that runs and is entirely wrong.

## Step 4: The evaluation script (pipeline/evaluate.py)

```python
"""Score the trained model on the test split and write evaluation.json for the quality gate."""
import json
import os
import tarfile

import pandas as pd
import xgboost as xgb
from sklearn.metrics import accuracy_score, classification_report, f1_score

BASE = os.environ.get("PROCESSING_DIR", "/opt/ml/processing")

with tarfile.open(f"{BASE}/model/model.tar.gz") as tar:
    tar.extractall(path=f"{BASE}/model")
booster = xgb.Booster()
booster.load_model(f"{BASE}/model/xgboost-model")      # the built-in container's file name

test = pd.read_csv(f"{BASE}/test/test.csv", header=None)
y_true = test.iloc[:, 0]
y_pred = booster.predict(xgb.DMatrix(test.iloc[:, 1:].values)).argmax(axis=1)

report = {"multiclass_classification_metrics": {
    "accuracy": {"value": float(accuracy_score(y_true, y_pred))},
    "macro_f1": {"value": float(f1_score(y_true, y_pred, average="macro"))},
}}
print(json.dumps(report, indent=2))
print(classification_report(y_true, y_pred, target_names=["unacc", "acc", "good", "vgood"],
                            digits=3))
os.makedirs(f"{BASE}/evaluation", exist_ok=True)
with open(f"{BASE}/evaluation/evaluation.json", "w") as f:
    json.dump(report, f)
```

- The training step hands over the model as a **tarball** (`model.tar.gz`), not as an unpacked folder, so the script unpacks it.
- The built-in XGBoost container always names the model file **`xgboost-model`**. A wrong name here is the most common reason this step fails minutes into an otherwise healthy run.
- **Macro F1** averages the F1 of all four classes equally, so the rare `good` and `vgood` classes count as much as `unacc`. Accuracy would be 70% for a model that always answers `unacc`.
- `evaluation.json` is how a number computed **inside** a container can steer the pipeline (Step 7).

## Step 5: Rehearse the pipeline locally (src/local\_rehearsal.py)

Each cloud step spends 2–3 minutes just starting a machine. Debugging a script by rerunning the pipeline is slow and costs money, so run the same scripts locally first, with the same folders and the same XGBoost settings.

```python
"""Run the pipeline's three scripts on your laptop, with the folders SageMaker would provide."""
import os
import shutil
import subprocess
import sys
import tarfile

import pandas as pd
import xgboost as xgb
from ucimlrepo import fetch_ucirepo

HYPERPARAMETERS = {"objective": "multi:softprob", "num_class": 4, "max_depth": 5,
                   "eta": 0.2, "subsample": 0.8, "eval_metric": "mlogloss", "seed": 0}
NUM_ROUND = 150
BASE = "local/processing"

shutil.rmtree("local", ignore_errors=True)
os.makedirs(f"{BASE}/input")
fetch_ucirepo(id=19).data.original.to_csv(f"{BASE}/input/car_evaluation.csv", index=False)
env = {**os.environ, "PROCESSING_DIR": BASE}

print("== processing step")
subprocess.run([sys.executable, "pipeline/preprocessing.py"], env=env, check=True)

print("== training step (same algorithm and settings as the built-in XGBoost container)")
train = pd.read_csv(f"{BASE}/output/train/train.csv", header=None)
val = pd.read_csv(f"{BASE}/output/validation/validation.csv", header=None)
dtrain = xgb.DMatrix(train.iloc[:, 1:].values, label=train.iloc[:, 0])
dval = xgb.DMatrix(val.iloc[:, 1:].values, label=val.iloc[:, 0])
booster = xgb.train(HYPERPARAMETERS, dtrain, NUM_ROUND, evals=[(dval, "validation")],
                    verbose_eval=50)
os.makedirs(f"{BASE}/model")
booster.save_model(f"{BASE}/model/xgboost-model")
with tarfile.open(f"{BASE}/model/model.tar.gz", "w:gz") as tar:
    tar.add(f"{BASE}/model/xgboost-model", arcname="xgboost-model")
os.remove(f"{BASE}/model/xgboost-model")
shutil.copytree(f"{BASE}/output/test", f"{BASE}/test")

print("== evaluation step")
subprocess.run([sys.executable, "pipeline/evaluate.py"], env=env, check=True)
```

## Step 7: Define and start the pipeline (src/run\_pipeline.py)

```python
"""Define the SageMaker Pipeline, create or update it, and start one execution."""
import boto3
import sagemaker
from sagemaker.estimator import Estimator
from sagemaker.image_uris import retrieve
from sagemaker.inputs import TrainingInput
from sagemaker.model_metrics import MetricsSource, ModelMetrics
from sagemaker.processing import ProcessingInput, ProcessingOutput, ScriptProcessor
from sagemaker.sklearn.processing import SKLearnProcessor
from sagemaker.workflow.condition_step import ConditionStep
from sagemaker.workflow.conditions import ConditionGreaterThanOrEqualTo
from sagemaker.workflow.fail_step import FailStep
from sagemaker.workflow.functions import Join, JsonGet
from sagemaker.workflow.parameters import ParameterFloat, ParameterString
from sagemaker.workflow.pipeline import Pipeline
from sagemaker.workflow.properties import PropertyFile
from sagemaker.workflow.step_collections import RegisterModel
from sagemaker.workflow.steps import ProcessingStep, TrainingStep

from src.config import BUCKET, MODEL_PACKAGE_GROUP, PIPELINE_NAME, PREFIX, REGION, ROLE_ARN

session = sagemaker.Session(boto_session=boto3.Session(region_name=REGION))
xgb_image = retrieve(framework="xgboost", region=REGION, version="1.7-1")

# Values you can change per execution without editing the pipeline.
input_data = ParameterString("InputData",
                             default_value=f"s3://{BUCKET}/{PREFIX}/input/car_evaluation.csv")
min_macro_f1 = ParameterFloat("MinMacroF1", default_value=0.85)

# 1. Processing: encode and split.
step_process = ProcessingStep(
    name="PreprocessCarData",
    processor=SKLearnProcessor(framework_version="1.2-1", role=ROLE_ARN,
                               instance_type="ml.m5.large", instance_count=1,
                               sagemaker_session=session),
    inputs=[ProcessingInput(source=input_data, destination="/opt/ml/processing/input")],
    outputs=[ProcessingOutput(output_name=n, source=f"/opt/ml/processing/output/{n}")
             for n in ("train", "validation", "test")],
    code="pipeline/preprocessing.py",
)
outputs = step_process.properties.ProcessingOutputConfig.Outputs

# 2. Training: SageMaker's built-in XGBoost, configured only by hyperparameters.
xgb = Estimator(image_uri=xgb_image, role=ROLE_ARN, instance_type="ml.m5.xlarge",
                instance_count=1, output_path=f"s3://{BUCKET}/{PREFIX}/models",
                sagemaker_session=session)
xgb.set_hyperparameters(objective="multi:softprob", num_class=4, num_round=150,
                        max_depth=5, eta=0.2, subsample=0.8, eval_metric="mlogloss", seed=0)
step_train = TrainingStep(
    name="TrainCarClassifier",
    estimator=xgb,
    inputs={"train": TrainingInput(outputs["train"].S3Output.S3Uri, content_type="text/csv"),
            "validation": TrainingInput(outputs["validation"].S3Output.S3Uri,
                                        content_type="text/csv")},
)

# 3. Evaluation: runs in the XGBoost image, because evaluate.py imports xgboost.
evaluation_report = PropertyFile(name="EvaluationReport", output_name="evaluation",
                                 path="evaluation.json")
step_eval = ProcessingStep(
    name="EvaluateCarClassifier",
    processor=ScriptProcessor(image_uri=xgb_image, command=["python3"], role=ROLE_ARN,
                              instance_type="ml.m5.large", instance_count=1,
                              sagemaker_session=session),
    inputs=[ProcessingInput(source=step_train.properties.ModelArtifacts.S3ModelArtifacts,
                            destination="/opt/ml/processing/model"),
            ProcessingInput(source=outputs["test"].S3Output.S3Uri,
                            destination="/opt/ml/processing/test")],
    outputs=[ProcessingOutput(output_name="evaluation", source="/opt/ml/processing/evaluation")],
    code="pipeline/evaluate.py",
    property_files=[evaluation_report],
)

# 4. Register only if macro F1 clears the bar; otherwise fail the execution loudly.
step_register = RegisterModel(
    name="RegisterCarClassifier",
    estimator=xgb,
    model_data=step_train.properties.ModelArtifacts.S3ModelArtifacts,
    content_types=["text/csv"],
    response_types=["text/csv"],
    inference_instances=["ml.m5.large"],
    transform_instances=["ml.m5.large"],
    model_package_group_name=MODEL_PACKAGE_GROUP,
    approval_status="PendingManualApproval",
    model_metrics=ModelMetrics(model_statistics=MetricsSource(
        s3_uri=Join(on="/", values=[
            step_eval.properties.ProcessingOutputConfig.Outputs["evaluation"].S3Output.S3Uri,
            "evaluation.json"]),
        content_type="application/json")),
)
macro_f1 = JsonGet(step_name=step_eval.name, property_file=evaluation_report,
                   json_path="multiclass_classification_metrics.macro_f1.value")
step_gate = ConditionStep(
    name="MacroF1Gate",
    conditions=[ConditionGreaterThanOrEqualTo(left=macro_f1, right=min_macro_f1)],
    if_steps=[step_register],
    else_steps=[FailStep(name="MacroF1TooLow",
                         error_message=Join(on=" ", values=["macro F1 below", min_macro_f1]))],
)

pipeline = Pipeline(name=PIPELINE_NAME, parameters=[input_data, min_macro_f1],
                    steps=[step_process, step_train, step_eval, step_gate],
                    sagemaker_session=session)

if __name__ == "__main__":
    pipeline.upsert(role_arn=ROLE_ARN)
    execution = pipeline.start()
    print(f"started: {execution.arn}")
    print("follow it with: python -m src.status")
```

How to read it:

- **Defining a step runs nothing.** Each step is a node in a graph; jobs start only on `pipeline.start()`. A typo in a path will not fail now; it fails minutes into the execution. That is why Step 5 exists.
- **`.properties...` references are placeholders**, resolved when the earlier step finishes. They also create the order: training reads the processing step's `train` output, so it runs after it. You never write an S3 path between steps.
- **`ScriptProcessor` with the XGBoost image for evaluation.** `evaluate.py` imports `xgboost`, which the scikit-learn processing container does not have. Running it in the XGBoost image guarantees the same XGBoost version that trained the model.
- **`PropertyFile` + `JsonGet`** read `macro_f1` from `evaluation.json` at run time and feed it to the condition.
- **`FailStep` in `else_steps`.** With an empty `else_steps`, a weak model would simply not be registered and the execution would still show **Succeeded**: a green run that hides a regression. The fail step makes it red.
- **`PendingManualApproval`**: passing the gate makes the model a *candidate*, not a deployment. Two brakes: an automatic metric threshold, then a human.
- **Parameters** (`InputData`, `MinMacroF1`) can be changed per execution, e.g. `pipeline.start(parameters={"MinMacroF1": 0.95})`.
- **`upsert`** creates the pipeline the first time and updates it afterwards, so the same command works in CI. It also re-uploads `pipeline/*.py`, so a fixed script is picked up on the next run.

## Step 8: Follow the execution (src/status.py)

```python
"""Show the latest pipeline execution, step by step, with failure reasons."""
import boto3

from src.config import PIPELINE_NAME, REGION

sm = boto3.client("sagemaker", region_name=REGION)
latest = sm.list_pipeline_executions(PipelineName=PIPELINE_NAME, SortBy="CreationTime",
                                     SortOrder="Descending", MaxResults=1)
arn = latest["PipelineExecutionSummaries"][0]["PipelineExecutionArn"]
status = sm.describe_pipeline_execution(PipelineExecutionArn=arn)["PipelineExecutionStatus"]
print(f"execution: {arn.split('/')[-1]}   status: {status}")

steps = sm.list_pipeline_execution_steps(PipelineExecutionArn=arn, SortOrder="Ascending")
for step in steps["PipelineExecutionSteps"]:
    print(f"  {step['StepName']:<38} {step['StepStatus']}")
    if step["StepStatus"] == "Failed":
        print(f"      reason: {step.get('FailureReason')}")
        meta = step.get("Metadata", {})
        job = meta.get("ProcessingJob") or meta.get("TrainingJob") or {}
        if job:
            print(f"      logs:   CloudWatch, job {job['Arn'].split('/')[-1]}")
```

```bash
python -m src.status      # run every few minutes
```

A successful execution takes about 10–15 minutes, mostly machines starting. When it finishes, every step shows `Succeeded`, including `RegisterCarClassifier-RegisterModel` (the SDK adds the `-RegisterModel` suffix). In the console, **SageMaker Studio → Pipelines → car-evaluation-pipeline** shows the same graph with each step coloured by status.

**When a step fails**, the step's `FailureReason` usually says only `AlgorithmError: See job logs for more information`: your script exited with an error. The real Python traceback is in **CloudWatch Logs**, under `/aws/sagemaker/ProcessingJobs` or `/aws/sagemaker/TrainingJobs`, in the stream named after the job printed by `status.py`. Fix the script, check it with `src.local_rehearsal`, then run `src.run_pipeline` again; `upsert` uploads the fixed code.

### src/deploy.py

```python
"""Deploy the newest APPROVED model version to a real-time endpoint. Billing starts now."""
import boto3

from sagemaker import ModelPackage

from src.config import ENDPOINT_NAME, MODEL_PACKAGE_GROUP, REGION, ROLE_ARN

sm = boto3.client("sagemaker", region_name=REGION)

    initial_instance_count=1, instance_type="ml.m5.large", endpoint_name=ENDPOINT_NAME)

```

## Step 10: Score two cars (src/predict.py)

```python
"""Score two cars through the endpoint. The row must use preprocessing.py's encoding and order."""
import boto3

from src.config import ENDPOINT_NAME, REGION

LABELS = ["unacc", "acc", "good", "vgood"]
# columns: buying, maint, doors, persons, lug_boot, safety (encoded as in ORDINAL_MAPS)
CARS = {
    "cheap, safe, roomy": "0,0,4,4,2,2",
    "pricey, unsafe, small": "3,3,2,2,0,0",
}

runtime = boto3.client("sagemaker-runtime", region_name=REGION)
for name, row in CARS.items():
    body = runtime.invoke_endpoint(EndpointName=ENDPOINT_NAME, ContentType="text/csv",
                                   Body=row)["Body"].read().decode()
    scores = [float(v) for v in body.strip().strip("[]").split(",")]
    best = max(range(4), key=scores.__getitem__)
    print(f"{name:<22} -> {LABELS[best]:<5} p={scores[best]:.3f}   {[round(s, 3) for s in scores]}")
```

```text
pricey, unsafe, small  -> unacc p=1.0     [1.0, 0.0, 0.0, 0.0]
```

The cloud model is trained by the same algorithm and settings, so expect the same verdicts. These two predictions are a sanity check the metrics cannot give: a cheap, safe, roomy car **should** be `vgood`. If they came back swapped, suspect the column order or encoding of the request, not the model.

```python
import boto3
```

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `AssertionError: unmapped category found` | A value not in `ORDINAL_MAPS` | Add it to the map; the assert stopped a silent `NaN` |
| `ModuleNotFoundError: No module named 'xgboost'` in evaluation | Evaluation run in the scikit-learn container | Use `ScriptProcessor` with the XGBoost image, as in Step 7 |
| `FileNotFoundError ... xgboost-model` | Wrong model file name in `evaluate.py` | The built-in container always writes `xgboost-model` |
| Execution `Failed`, reason `AlgorithmError: See job logs` | Your script raised an error | Read CloudWatch for that job; fix; rerun `src.local_rehearsal` |
| `AccessDenied` on an S3 path you can see | Region mismatch, or the role lacks bucket access | Same region for bucket and pipeline; grant the role read/write |
| Execution `Failed` at `MacroF1TooLow` | The model missed the quality bar | Working as designed; read `evaluation.json` |
| `deploy` finds no approved version (`IndexError`) | Nothing approved yet | Run `src.approve` (or approve in Studio) |
| Endpoint answers, but nonsense | Request columns in the wrong order or not encoded | Encode exactly as `ORDINAL_MAPS`, in the same column order |
