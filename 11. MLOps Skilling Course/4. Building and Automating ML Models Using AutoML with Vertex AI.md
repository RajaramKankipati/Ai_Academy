# Building and Automating ML Models Using AutoML with Vertex AI

## Overview

You will train a 7-class obesity classifier without choosing an algorithm or settings yourself. Google Cloud's **Vertex AI AutoML** searches over model types and settings for you. You then evaluate the winning model, deploy it to an endpoint, ask it for a live prediction, and shut it down.

By the end, you will be able to:

- Set up a Google Cloud project, a Cloud Storage bucket and credentials from the terminal.
- Register a CSV as a Vertex AI dataset and launch an AutoML training job.
- Read AutoML's evaluation metrics and check them against a local baseline.
- Deploy a model to an endpoint, call it, and delete it to stop billing.

**Prerequisites:** Python 3.11, a **Google Cloud project with billing enabled**, and the [`gcloud` CLI](https://cloud.google.com/sdk/docs/install). Steps 1–6 are free and run locally. **Steps 8–12 cost money**: one AutoML training node-hour, plus about an hour of endpoint time. Do Step 12 (clean up) the same day.

**Dataset:** [UCI Estimation of Obesity Levels](https://archive.ics.uci.edu/dataset/544), 2,111 survey answers about diet, exercise and transport, labelled with one of 7 weight classes (`NObeyesdad`). It mixes text and number columns, which is the kind of table AutoML is built for. It is downloaded automatically by the code.

**What AutoML does:** in Sessions 1–3 you chose the model (random forest) and its settings. With AutoML you hand over a table and the name of the target column; a managed service tries many model families and settings and returns the best one. You trade control for speed.

### src/state.py

Each Vertex AI object (dataset, model, endpoint) has a long **resource name** like `projects/123/locations/us-central1/endpoints/456`. Each script saves the names it creates in `state.json`, so the next script can find them without you copying IDs by hand.

```python
"""Save and load Vertex AI resource names between scripts."""
import json
import os

from src.config import STATE_FILE


def load():
    if not os.path.exists(STATE_FILE):
        return {}
    with open(STATE_FILE) as f:
        return json.load(f)


def save(**values):
    state = load()
    state.update(values)
    with open(STATE_FILE, "w") as f:
        json.dump(state, f, indent=2)
```

## Step 5: Build a local baseline

Before paying for AutoML, find out what a plain random forest scores on your laptop. Then you will know whether AutoML actually adds anything.

### src/baseline.py

```python
"""A hand-built local model, so we know what AutoML has to beat."""
import pandas as pd
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score, log_loss
from sklearn.model_selection import train_test_split

from src.config import DATA_FILE, TARGET

df = pd.read_csv(DATA_FILE)
X = pd.get_dummies(df.drop(columns=[TARGET]))
y = df[TARGET]
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.15, random_state=42, stratify=y)

for name, cols in [("all features", X.columns),
                   ("without Height/Weight", [c for c in X.columns
                                              if c not in ("Height", "Weight")])]:
    model = RandomForestClassifier(n_estimators=300, random_state=42)
    model.fit(X_tr[cols], y_tr)
    proba = model.predict_proba(X_te[cols])
    print(f"{name:<22} accuracy={accuracy_score(y_te, model.predict(X_te[cols])):.3f} "
          f"log_loss={log_loss(y_te, proba, labels=model.classes_):.3f}")
```

```bash
python -m src.baseline
```

```text
all features           accuracy=0.950 log_loss=0.288
without Height/Weight  accuracy=0.858 log_loss=0.578
```

**Watch out for built-in leakage.** The weight classes are largely defined by BMI, which is weight ÷ height². Height and weight are also input columns, so a model can simply rediscover the BMI formula. Removing those two columns drops accuracy from 0.95 to 0.86. Keep this in mind when AutoML reports a near-perfect score in Step 9: most of that score comes from height and weight, not from lifestyle habits.

**Log loss** measures how confident and correct the predicted probabilities are. Lower is better; 0 is perfect. We use it because AutoML optimises it in Step 8.

## Step 6: Create a bucket and upload the data

Vertex AI reads training data from Cloud Storage, not from your disk.

```bash
gcloud storage buckets create gs://your-mlops-bucket \
```


The bucket must be in the **same region** as your Vertex AI work (`us-central1`). If the bucket already exists, `buckets create` returns `409 ... you already own it`, which is safe to ignore.

Check the `ls` output for the exact file name. A wrong path in `cp` (e.g. a trailing `/`) can create a folder instead of a file, and Step 7 would then not find the CSV.

## Step 8: Launch AutoML training (costs money)

### src/train\_automl.py

```python
"""Launch an AutoML classification job. Blocks until training finishes."""
from google.cloud import aiplatform

from src import state
from src.config import BUCKET_URI, PROJECT_ID, REGION, TARGET

aiplatform.init(project=PROJECT_ID, location=REGION, staging_bucket=BUCKET_URI)
dataset = aiplatform.TabularDataset(state.load()["dataset"])

column_transformations = [
    {"auto": {"column_name": col}} for col in dataset.column_names if col != TARGET
]
print(f"{len(column_transformations)} input columns (target excluded)")

job = aiplatform.AutoMLTabularTrainingJob(
    display_name="obesity-automl-job",
    optimization_prediction_type="classification",
    optimization_objective="minimize-log-loss",
    column_transformations=column_transformations,
)

model = job.run(
    dataset=dataset,
    target_column=TARGET,
    training_fraction_split=0.7,
    validation_fraction_split=0.15,
    test_fraction_split=0.15,
    budget_milli_node_hours=1000,   # 1 node-hour, the minimum
    model_display_name="obesity-automl-model",
    disable_early_stopping=False,
    additional_experiments=["disable_nn"],
)
state.save(model=model.resource_name)
print(f"Model: {model.resource_name}")
```

What each part does:

- **`column_transformations`** tells AutoML how to treat each input. `"auto"` lets it decide (number vs category). **The target must not be in this list**; otherwise the model gets the answer as an input. The script prints `16 input columns (target excluded)` so you can check.
- **`minimize-log-loss`** asks for well-calibrated probabilities across all 7 classes, not just the right top answer.
- **70 / 15 / 15 split**: AutoML trains on 70%, tunes on 15%, and reports final scores on a 15% it never trained on.
- **`budget_milli_node_hours=1000`** = 1 node-hour, the smallest budget allowed. You pay for this.
- **`disable_nn`** skips neural networks. On a small table, tree models usually win anyway, and training finishes sooner.

```bash
python -m src.train_automl
```

The script prints a **View Training** console link, then `PIPELINE_STATE_RUNNING` every minute or so. **This is normal**; training takes about an hour. When it finishes:

```text
AutoMLTabularTrainingJob run completed. Resource name: projects/.../trainingPipelines/...
Model: projects/123456789/locations/us-central1/models/111222333
```

If the state becomes `PIPELINE_STATE_FAILED`, open the console link. It shows the real reason (usually a data problem), which the Python error often hides. Do not just run the script again.

## Step 9: Evaluate the model

### src/evaluate.py

```python
"""Print the evaluation metrics AutoML computed on its test split."""
from google.cloud import aiplatform

from src import state
from src.config import PROJECT_ID, REGION

aiplatform.init(project=PROJECT_ID, location=REGION)
model = aiplatform.Model(state.load()["model"])
```

## Step 10: Deploy to an endpoint (costs money per hour)

An **endpoint** is a managed web service that serves predictions. It bills every hour it is deployed, whether or not anyone calls it.

### src/deploy.py

```python
"""Deploy the model to a new endpoint. Billing starts now."""
from google.cloud import aiplatform

from src import state
from src.config import PROJECT_ID, REGION

aiplatform.init(project=PROJECT_ID, location=REGION)
model = aiplatform.Model(state.load()["model"])

endpoint = aiplatform.Endpoint.create(display_name="obesity-automl-endpoint")
state.save(endpoint=endpoint.resource_name)   # saved before the slow part
print(f"Endpoint created: {endpoint.resource_name}")

model.deploy(endpoint=endpoint, machine_type="n1-standard-4",
             min_replica_count=1, max_replica_count=1)
print("Model deployed.")
```

```bash
python -m src.deploy
```

Deployment takes 10–20 minutes.

We create the endpoint first and save its name, **then** deploy. That order matters if the deploy step fails with a network error such as:

```text
grpc._channel._InactiveRpcError: ... status = StatusCode.UNAVAILABLE
details = "errors resolving us-central1-aiplatform.googleapis.com:443: ... Could not contact DNS servers"
```

That is your laptop losing its connection while **waiting**. The deployment keeps running on Google's side. **Do not run `deploy` again**; that would create a second endpoint and double the bill. Instead, open **Vertex AI → Online prediction → Endpoints** in the console and wait for the model to show as deployed. The endpoint name is already in `state.json`, so Step 11 works as soon as it is ready.

Errors that say `PERMISSION_DENIED` or `INVALID_ARGUMENT` are real failures and do need fixing.

## Step 11: Get a prediction

### src/predict.py

```python
"""Send one person's data to the endpoint and print the class scores."""
from google.cloud import aiplatform

from src import state
from src.config import PROJECT_ID, REGION

aiplatform.init(project=PROJECT_ID, location=REGION)
endpoint = aiplatform.Endpoint(state.load()["endpoint"])

# Every value is sent as a string, even the numbers.
instance = {
    "Gender": "Male", "Age": "27.0", "Height": "1.8", "Weight": "87.0",
    "family_history_with_overweight": "no", "FAVC": "no", "FCVC": "3.0", "NCP": "3.0",
    "CAEC": "Sometimes", "SMOKE": "no", "CH2O": "2.0", "SCC": "no", "FAF": "2.0",
    "TUE": "0.0", "CALC": "Frequently", "MTRANS": "Walking",
}

result = endpoint.predict(instances=[instance]).predictions[0]
scores = dict(zip(result["classes"], result["scores"]))
for cls, score in sorted(scores.items(), key=lambda kv: -kv[1]):
    print(f"  {cls:<22} {score:.4f}")
```

```bash
python -m src.predict
```

One run printed (top lines):

```text
  Overweight_Level_I     0.9430
  Overweight_Level_II    0.0550
  ...
```

- **Every value is a string**, even `"27.0"`. AutoML tabular endpoints expect strings; sending plain numbers gives a schema error that has nothing to do with the model.
- **AutoML returns a score for every class**, as two matching lists, `classes` and `scores`. We zip them and sort to find the winner.
- **Look at the gap, not just the winner.** One class near 1.0 means the model is confident. Several classes close together mean the input sits on a boundary, and the top label is much less certain.

This person is row 3 of the dataset, labelled `Overweight_Level_I`, so the prediction is correct.

## Step 12: Clean up (do not skip)

### src/cleanup.py

```python
"""Undeploy and delete the endpoint so it stops billing."""
from google.cloud import aiplatform

from src import state
from src.config import PROJECT_ID, REGION

aiplatform.init(project=PROJECT_ID, location=REGION)
endpoint = aiplatform.Endpoint(state.load()["endpoint"])
endpoint.undeploy_all()
endpoint.delete()
print("Endpoint undeployed and deleted.")
```

```bash
python -m src.cleanup
```

Then open **Vertex AI → Online prediction → Endpoints** in the console and confirm the list is empty. The script only proves the Python calls returned. The console is the only proof that nothing is still billing.

The dataset, the model and the bucket cost little or nothing while idle. To remove everything, delete the bucket with `gcloud storage rm -r gs://your-mlops-bucket`, and delete the model in **Vertex AI → Model Registry**.

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `DefaultCredentialsError` in Python | Only ran `gcloud auth login` | Also run `gcloud auth application-default login` |
| `403 ... aiplatform.googleapis.com has not been used in project` | Vertex AI API not enabled | `gcloud services enable aiplatform.googleapis.com` |
| `409 ... you already own it` creating the bucket | Bucket exists from an earlier run | Ignore it and continue |
| `403 Forbidden` reading the bucket during training | Bucket in another project, or permissions missing | Use a bucket in the same project and region as `config.py` |
| `KeyError: 'dataset'` (or `'model'`, `'endpoint'`) | An earlier step did not finish, so `state.json` lacks the name | Run the earlier script first |
| `PIPELINE_STATE_FAILED` | Usually a data problem | Open the **View Training** link and read the reason |
| `UNAVAILABLE ... Could not contact DNS servers` during deploy | Your network dropped while waiting | Do not redeploy; wait in the console, then run `predict` |
| `400 Bad Request` on predict, mentioning the input format | Sent numbers instead of strings | Quote every value in the request |
| Unexpected bill | Endpoint still deployed | Run `cleanup`, then check the Endpoints page |
