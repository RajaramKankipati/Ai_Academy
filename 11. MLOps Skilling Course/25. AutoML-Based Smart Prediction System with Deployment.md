# AutoML-Based Smart Prediction System with Deployment

## Overview

Sessions 4 and 9 used cloud AutoML: powerful, but it needs a cloud account and billing, and takes about an hour. In this session you get an automatic search over model types and settings **on your laptop, for free, in 60 seconds**, using Microsoft Research's open-source **FLAML**. Then you serve the winning model with FastAPI.

FLAML (Fast and Lightweight AutoML) takes a training table, a task, a metric and a **time budget in seconds**. It tries LightGBM, XGBoost, random forests and extra trees with different settings, starting with cheap configurations and moving to expensive ones only when the cheap ones stop improving. When time runs out, it returns the best model as an ordinary Python object.

| | Cloud AutoML (Sessions 4, 9) | FLAML (this session) |
| --- | --- | --- |
| Runs on | Managed cloud machines | Your laptop |
| Cost | Billed node-hours | Nothing |
| Needs | Cloud project, billing, permissions | `pip install` |
| Budget | Node-hours | Seconds |
| Output | A hosted model and endpoint | A plain model object you serve yourself |

By the end, you will be able to:

- Record baselines **before** running AutoML, so its result has something to beat.
- Run a time-budgeted FLAML search and read its trace to tell "converged" from "cut off".
- Inspect and export the winning model with its input contract.
- Serve it with FastAPI, without FLAML installed at serving time.

**Prerequisites:** Python 3.11 and Session 7. Everything runs locally.

**Dataset:** [UCI Abalone](https://archive.ics.uci.edu/dataset/1/abalone), 4,177 sea snails measured in Tasmania: sex (`M`, `F`, `I` for infant), length, diameter, height and four weights. The target, `Rings`, is counted by cutting and staining the shell under a microscope (age ≈ rings + 1.5 years). A model that predicts it from cheap outside measurements would replace a tedious task. It is a **regression** problem, and a famously hard one: the measurements explain only about half the variation in age. That makes it an honest test of how much AutoML adds. It is downloaded automatically by the code.

## Step 3: Load and split (src/data.py)

```python
"""Load UCI Abalone and split it once."""
from sklearn.model_selection import train_test_split


def load_split():
    from ucimlrepo import fetch_ucirepo

    ds = fetch_ucirepo(id=1)
    X, y = ds.data.features.copy(), ds.data.targets["Rings"]
    X["Sex"] = X["Sex"].astype("category")       # FLAML handles category columns itself
    return train_test_split(X, y, test_size=0.2, random_state=7)
```

No one-hot encoding, scaling or imputation: FLAML handles a `category` column correctly for each model type. **The `astype("category")` line is essential.** Left as text, LightGBM and XGBoost trials fail on the string `"M"`, FLAML drops them and carries on, and you get a worse model with no visible error.

The 20% test set is never shown to FLAML. FLAML runs its own cross-validation **inside** the training data; if it saw the test rows, the final score would describe data it optimised against.

## Step 4: Baselines first (src/baseline.py)

Run this **before** AutoML. Without a baseline on record, any AutoML number looks impressive.

```python
"""Two baselines to beat: predict the average, and a plain linear regression."""
import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

from src.data import load_split

X_tr, X_te, y_tr, y_te = load_split()
print(f"train {X_tr.shape}, test {X_te.shape}; Rings mean {y_tr.mean():.2f}, std {y_tr.std():.2f}")

Xtr, Xte = pd.get_dummies(X_tr), pd.get_dummies(X_te)[pd.get_dummies(X_tr).columns]
linear = LinearRegression().fit(Xtr, y_tr).predict(Xte)
mean_only = np.full(len(y_te), y_tr.mean())
for name, pred in [("predict the mean", mean_only), ("linear regression", linear)]:
    print(f"{name:<18} RMSE {mean_squared_error(y_te, pred) ** 0.5:.4f}   "
          f"MAE {mean_absolute_error(y_te, pred):.4f}   R2 {r2_score(y_te, pred):.4f}")
```

## Step 5: Run the search (src/search.py)

```python
"""Let FLAML search for the best model in a fixed time budget, then export the winner.

Usage: python -m src.search [seconds]
"""
import json
import sys
from datetime import datetime, timezone

import joblib
from flaml import AutoML
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

from src.data import load_split

budget = int(sys.argv[1]) if len(sys.argv) > 1 else 60
X_tr, X_te, y_tr, y_te = load_split()

automl = AutoML()
automl.fit(X_train=X_tr, y_train=y_tr, task="regression", metric="rmse",
           time_budget=budget, estimator_list=["lgbm", "xgboost", "rf", "extra_tree"],
           eval_method="cv", n_splits=5, n_jobs=4, log_file_name="model/search.log", seed=7,
           verbose=0)

print(f"best estimator : {automl.best_estimator}")
print(f"best CV RMSE   : {automl.best_loss:.4f}")
print(f"improvements   : {len(automl.config_history)}")
print(f"best config    : {json.dumps(automl.best_config)}")

pred = automl.predict(X_te)
metrics = {"rmse": round(float(mean_squared_error(y_te, pred)) ** 0.5, 4),
           "mae": round(float(mean_absolute_error(y_te, pred)), 4),
           "r2": round(float(r2_score(y_te, pred)), 4)}
print(f"test           : {metrics}")

joblib.dump({
    "model": automl.model.estimator,                  # a plain LightGBM/XGBoost/sklearn model
    "features": X_tr.columns.tolist(),
    "sex_categories": X_tr["Sex"].cat.categories.tolist(),
    "estimator": automl.best_estimator,
    "metrics": metrics,
    "trained_at": datetime.now(timezone.utc).isoformat(timespec="seconds"),
}, "model/abalone.joblib")
print("saved model/abalone.joblib")
```

| Argument | Meaning |
| --- | --- |
| `task="regression"`, `metric="rmse"` | What kind of problem, and what "best" means |
| `time_budget=60` | Wall-clock seconds; FLAML returns the best model found when time runs out |
| `estimator_list` | Model families to try |
| `eval_method="cv"`, `n_splits=5` | Score each configuration by 5-fold cross-validation on the training data |
| `n_jobs=4` | Threads per trial. Letting every library use every core can make trials **slower** through thread contention |
| `log_file_name` | One JSON line per improving trial (Step 6 reads it) |

A search limited by **time** depends on your computer's speed, so your winner and numbers may differ a little. Compare with the baseline:

| | Linear regression | FLAML (60 s) |
| --- | --- | --- |
| Test RMSE | 2.2633 | **2.2267** |
| Test MAE | 1.6038 | **1.5278** |
| Test R² | 0.5435 | **0.5582** |

The honest summary: **a small but real gain**, RMSE 1.6% lower, MAE 4.7% lower (typical errors shrink more than the worst ones). This dataset has a low ceiling: shell measurements simply do not pin down age. A minute of unattended compute for a few percent is a fine trade, but not the order-of-magnitude story AutoML marketing suggests.

One more check: the **test** RMSE (2.23) is worse than the **cross-validated** RMSE FLAML reported (2.11). Part of that is this particular test split being harder (even "predict the mean" scores 3.36 on it, against a training standard deviation of 3.19). Part is that a score used to **choose** the best of many configurations is always a little optimistic. Always judge the winner on data the search never saw.

## Step 6: Read the search trace (src/trace.py)

The final score is one number. The trace shows whether the time budget was enough.

```python
"""When did the search improve? FLAML logs one JSON line per improving trial."""
import json

records = [json.loads(line) for line in open("model/search.log") if line.startswith("{")]
improvements = [r for r in records if "validation_loss" in r]
for r in improvements:
    print(f"{r['wall_clock_time']:6.1f}s  RMSE {r['validation_loss']:.4f}  {r['learner']:<11} "
          f"n_estimators={r['config'].get('n_estimators')}")
print(f"last improvement at {improvements[-1]['wall_clock_time']:.1f}s")
```

```bash
python -m src.trace
```

```text
   0.1s  RMSE 2.8209  lgbm        n_estimators=4
   0.2s  RMSE 2.6557  lgbm        n_estimators=4
   0.2s  RMSE 2.2221  lgbm        n_estimators=7
   0.3s  RMSE 2.1877  lgbm        n_estimators=17
   0.6s  RMSE 2.1467  lgbm        n_estimators=55
   5.1s  RMSE 2.1426  lgbm        n_estimators=91
   8.2s  RMSE 2.1335  lgbm        n_estimators=100
  15.2s  RMSE 2.1244  rf          n_estimators=59
  24.3s  RMSE 2.1118  xgboost     n_estimators=34
  37.8s  RMSE 2.1118  xgboost     n_estimators=89
last improvement at 37.8s
```

Two patterns to read:

- **Cheap first.** The first trials use 4–17 trees and finish in a fraction of a second; larger models come later. That cost-aware order is why 60 seconds produces something useful rather than one half-trained big model.
- **The curve flattened.** RMSE fell by 0.68 in the first second and by only 0.03 in the next 37; the last change (at 37.8 s) did not move the rounded score. With nothing improving in the final 22 seconds, the search had **converged**; a 10× bigger budget would mostly be wasted.

The opposite pattern, improvements still arriving in the last seconds, means the search was **cut off** while still getting better. Rerun with a bigger budget before trusting the model. The final score alone cannot tell these two cases apart.

## Step 7: What was exported

`search.py` saved a bundle, not just the model:

```bash
python -c "import joblib; b = joblib.load('model/abalone.joblib'); print(type(b['model']).__name__, b['sex_categories'], b['estimator'])"
```

```text
XGBRegressor ['F', 'I', 'M'] xgboost
```

- **`automl.model.estimator`** is a plain `XGBRegressor` (or `LGBMRegressor`, etc.). Saving it, rather than the `AutoML` object, means the service needs only XGBoost, not FLAML.
- **`features`** fixes the column order.
- **`sex_categories` = `['F', 'I', 'M']`**, in alphabetical order, not the order values appear in the data. Tree libraries encode categories by **position**; a service that rebuilt the category list in another order would feed the model an `F` where it learned `M` and return confident, wrong numbers with no error. Storing the list fixes that.

## Step 8: Serve it (app/main.py)

```python
"""Serve the FLAML winner. Only the winning library (not FLAML) is needed here."""
import joblib
import pandas as pd
from fastapi import FastAPI
from pydantic import BaseModel, Field

BUNDLE = joblib.load("model/abalone.joblib")
MODEL, FEATURES, SEX_CATS = BUNDLE["model"], BUNDLE["features"], BUNDLE["sex_categories"]

app = FastAPI(title="Abalone age estimator")


class Abalone(BaseModel):
    Sex: str = Field(..., pattern="^[MFI]$")      # M, F or I (infant)
    Length: float = Field(..., gt=0)
    Diameter: float = Field(..., gt=0)
    Height: float = Field(..., ge=0)
    Whole_weight: float = Field(..., gt=0)
    Shucked_weight: float = Field(..., gt=0)
    Viscera_weight: float = Field(..., gt=0)
    Shell_weight: float = Field(..., gt=0)


@app.get("/health")
def health():
    return {"status": "ok", "estimator": BUNDLE["estimator"], "metrics": BUNDLE["metrics"],
            "trained_at": BUNDLE["trained_at"]}


@app.post("/predict")
def predict(item: Abalone):
    row = pd.DataFrame([item.model_dump()])[FEATURES]                  # training column order
    row["Sex"] = pd.Categorical(row["Sex"], categories=SEX_CATS)        # training category order
    rings = float(MODEL.predict(row)[0])
    return {"predicted_rings": round(rings, 2), "estimated_age_years": round(rings + 1.5, 1),
            "model": BUNDLE["estimator"]}
```

The two lines marked with comments are the serving contract: training **column order** and training **category order**. Both defend against silent wrongness rather than crashes. `pattern="^[MFI]$"` rejects `"male"` with a `422` instead of passing an unknown category that the model would quietly treat as missing.

### tests/test\_app.py

```python
from fastapi.testclient import TestClient

from app.main import app

client = TestClient(app)
FIRST_ROW = {"Sex": "M", "Length": 0.455, "Diameter": 0.365, "Height": 0.095,
             "Whole_weight": 0.514, "Shucked_weight": 0.2245, "Viscera_weight": 0.101,
             "Shell_weight": 0.15}


def test_health_reports_the_model():
    body = client.get("/health").json()
    assert body["status"] == "ok" and "rmse" in body["metrics"]


def test_prediction_is_a_plausible_ring_count():
    rings = client.post("/predict", json=FIRST_ROW).json()["predicted_rings"]
    assert 1 <= rings <= 29


def test_key_order_does_not_change_the_answer():
    shuffled = dict(reversed(list(FIRST_ROW.items())))
    assert client.post("/predict", json=shuffled).json() == client.post("/predict", json=FIRST_ROW).json()


def test_invalid_sex_is_rejected():
    assert client.post("/predict", json=dict(FIRST_ROW, Sex="male")).status_code == 422
```

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| Search only tries `rf` and `extra_tree` | `flaml` installed without `[automl]` | `pip install "flaml[automl]"` |
| No `lgbm`/`xgboost` lines in the trace, worse result | `Sex` still text, not `category`, so those trials fail | `X["Sex"] = X["Sex"].astype("category")` |
| Very few trials in the budget | Thread contention between libraries | Set `n_jobs` to your core count or less |
| `No model is trained` | Budget too short for one cross-validated fit | Give at least ~10 seconds |
| Results differ between runs or machines | The budget is wall-clock time | Expected; compare on the same machine, or fix `max_iter` instead |
| `ModuleNotFoundError: No module named 'xgboost'` in the service | The winner's library is not installed where you serve | Install the library named in `/health`'s `estimator` |
| Confident but wrong predictions | Category order or column order rebuilt differently | Use `sex_categories` and `features` from the bundle |
