# E2E MLOps Pipeline for Smart Healthcare Monitoring

## Overview

You will build the full loop for a clinical risk model: clean messy patient records, train a chronic-kidney-disease (CKD) classifier that copes with missing lab results, choose its decision threshold from the cost of each kind of mistake, serve it as an API, and check every incoming batch of patients before trusting its scores.

Clinical data breaks the usual pipeline in two ways, and this lab is about both:

1. **Missing lab values are normal, and they carry information.** A value is missing because nobody ordered that test, and *whether a test was ordered* says something about the patient. Dropping incomplete rows throws away most of the data and skews what is left.
2. **The two kinds of error do not cost the same.** Sending a sick patient home is far worse than sending a healthy one for a confirmatory test. Accuracy is the wrong yardstick, and 0.5 is not automatically the right threshold.

By the end, you will be able to:

- Clean text values that break labels silently (`"ckd\t"` as a third class).
- Measure whether missingness is related to the outcome, and keep that signal with missing-value indicators.
- Put all preprocessing **inside** the saved model, so the API handles missing values exactly like training did.
- Choose a threshold from error costs, using training data only.
- Check each incoming batch for completeness, drift in values, drift in missingness and an abnormal flag rate.

**Prerequisites:** Python 3.11 and Session 7 (FastAPI). Steps 1–10 run locally. Step 11 (optional) deploys to Cloud Run as in Session 13 and needs a Google Cloud project.

**Dataset:** [UCI Chronic Kidney Disease](https://archive.ics.uci.edu/dataset/336/chronic+kidney+disease), 400 patient records from a hospital in India: blood pressure, blood chemistry (creatinine, urea, haemoglobin, sodium, potassium, ...), urine tests, and history (hypertension, diabetes, anaemia), labelled `ckd` or `notckd`. It is genuinely messy: 60% of records miss at least one value, and some text values carry stray tab characters. It is downloaded automatically by the code.

> This is a teaching exercise on a public research dataset. A model like this is a *triage aid*, never a diagnosis. Using one on real patients needs regulatory and clinical-governance work far beyond an MLOps course.

## Step 3: Load and clean (src/data.py)

```python
"""Load the UCI Chronic Kidney Disease data and clean the text values."""
import numpy as np
import pandas as pd

NUMERIC = ["age", "bp", "sg", "al", "su", "bgr", "bu", "sc", "sod", "pot",
           "hemo", "pcv", "wbcc", "rbcc"]
CATEGORICAL = ["rbc", "pc", "pcc", "ba", "htn", "dm", "cad", "appet", "pe", "ane"]
FEATURES = NUMERIC + CATEGORICAL
TARGET = "class"


def load_ckd():
    from ucimlrepo import fetch_ucirepo   # only needed for training, not in the service

    df = fetch_ucirepo(id=336).data.original.copy()
    # The source file has values like "ckd\t" and "\tno": strip them, or "ckd\t"
    # becomes a third class and "\tno" a third answer.
    for col in df.select_dtypes("object").columns:
        df[col] = df[col].str.strip().replace({"?": np.nan, "": np.nan})
    df[NUMERIC] = df[NUMERIC].apply(pd.to_numeric, errors="coerce")
    df["label"] = (df[TARGET] == "ckd").astype(int)
    return df
```

Without the `strip()`, the raw `class` column has **three** values: `ckd` (248), `notckd` (150) and `ckd\t` (2). Two sick patients would silently be labelled healthy by `== "ckd"`. Likewise `dm` (diabetes) has `no`, `yes` and `\tno`.

Some column codes you will meet: `sc` serum creatinine, `hemo` haemoglobin, `bu` blood urea, `bgr` blood glucose, `pcv` packed cell volume, `rbc`/`rbcc` red blood cells, `wbcc` white blood cell count, `htn` hypertension, `dm` diabetes.

- **`dropna()` would keep 158 of 400 patients.** It would also not drop them at random.
- **Missing goes with sick.** Patients with no red-blood-cell result have CKD 94% of the time; patients with one, 43%. In this hospital, a missing test is a strong clue. Statisticians call this **missing not at random (MNAR)**.

Two consequences shape the rest of the lab:

1. Fill in missing values, but **also** give the model a yes/no column saying "this value was missing", so it can use that clue.
2. **Monitor missingness** in incoming data. If the way tests are ordered changes, "missing" stops meaning what the model learned, even if no lab value changes at all.

## Step 5: Train and choose a threshold (src/train.py)

```python
"""Train the CKD risk model, choose a screening threshold, and save it with a baseline."""
import json

import joblib
import numpy as np
from sklearn.compose import ColumnTransformer
from sklearn.ensemble import RandomForestClassifier
from sklearn.impute import SimpleImputer
from sklearn.metrics import confusion_matrix, roc_auc_score
from sklearn.model_selection import cross_val_predict, train_test_split
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

from src.data import CATEGORICAL, FEATURES, NUMERIC, load_ckd

COST_MISSED_CKD = 10     # a sick patient sent home
COST_FALSE_ALARM = 1     # a healthy patient sent for a confirmatory test

df = load_ckd()
X, y = df[FEATURES], df["label"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=42)

pipe = Pipeline([
    ("prep", ColumnTransformer([
        ("num", Pipeline([
            ("impute", SimpleImputer(strategy="median", add_indicator=True)),
            ("scale", StandardScaler()),
        ]), NUMERIC),
        ("cat", Pipeline([
            ("impute", SimpleImputer(strategy="constant", fill_value="unknown")),
            ("onehot", OneHotEncoder(handle_unknown="ignore")),
        ]), CATEGORICAL),
    ])),
    ("clf", RandomForestClassifier(n_estimators=300, min_samples_leaf=2,
                                   class_weight="balanced_subsample", random_state=42)),
])

# Choose the threshold from cross-validated scores on the TRAINING set only,
# by the cost of each kind of mistake. Ties go to the lower (safer) threshold.
cv_scores = cross_val_predict(pipe, X_train, y_train, cv=5, method="predict_proba")[:, 1]
print("threshold  missed_ckd  false_alarms  cost   (5-fold CV on training data)")
best = None
for t in np.arange(0.10, 0.91, 0.05).round(2):
    missed = int(((cv_scores < t) & (y_train == 1)).sum())
    alarms = int(((cv_scores >= t) & (y_train == 0)).sum())
    cost = COST_MISSED_CKD * missed + COST_FALSE_ALARM * alarms
    print(f"   {t:.2f}        {missed:>3}          {alarms:>3}       {cost:>3}")
    if best is None or cost < best[1]:
        best = (t, cost)
threshold = float(best[0])

pipe.fit(X_train, y_train)
n_features = pipe.named_steps["prep"].transform(X_train.head(1)).shape[1]
print(f"train {len(X_train)} / test {len(X_test)} patients, {n_features} model inputs")
print(f"chosen threshold: {threshold:.2f} (lowest cost)")

proba = pipe.predict_proba(X_test)[:, 1]
print(f"test ROC AUC: {roc_auc_score(y_test, proba):.4f}")
for name, t in [("default 0.5", 0.5), ("screening", threshold)]:
    tn, fp, fn, tp = confusion_matrix(y_test, (proba >= t).astype(int)).ravel()
    print(f"  {name:<12} threshold {t:.3f}:  TN {tn:>2}  FP {fp:>2}  FN {fn:>2}  TP {tp:>2}  "
          f"recall {tp / (tp + fn):.3f}")

baseline = {
    "threshold": round(threshold, 4),
    "flag_rate": round(float((pipe.predict_proba(X_train)[:, 1] >= threshold).mean()), 4),
    "missing_rates": X_train.isna().mean().round(4).to_dict(),
}
joblib.dump({"pipeline": pipe, "threshold": threshold}, "model/ckd.joblib")
X_train.to_csv("model/reference.csv", index=False)
with open("model/baseline.json", "w") as f:
    json.dump(baseline, f, indent=2)
print("saved model/ckd.joblib, model/reference.csv, model/baseline.json")
```

What each part does:

- **All preprocessing is inside the `Pipeline`.** The imputers, scaler and encoder are saved with the model. An API receiving a patient with missing labs then handles it exactly as training did. Cleaning data in separate code before `fit` is the most common way a model that worked in a notebook fails in production with `ValueError: Input contains NaN`.
- **`add_indicator=True`** adds one yes/no "was missing" column for each numeric lab that had gaps: the MNAR clue from Step 4.
- **`class_weight="balanced_subsample"`** gives the smaller class more weight, instead of inventing synthetic patients by oversampling 300 rows.
- **The threshold is chosen from costs, on training data only.** `cross_val_predict` scores every training patient with a model that did not see them. Choosing the threshold on the **test** set would leak test information into the model, and the test score would no longer be honest. Here a missed CKD case costs 10 and a false alarm costs 1, a policy a clinician would set, not a data scientist.

How to read it:

- **The cost table is the thing to show a clinician**, not the AUC. It says what each threshold buys: lower thresholds send more healthy people for tests; higher ones start missing sick patients.
- **The cliff is close.** At 0.55 nothing is missed in cross-validation, but at 0.65 two sick patients are sent home. A threshold sitting 0.1 from a cliff is fragile: a small shift in the incoming population could push patients over it. That is one reason to monitor (Step 8).
- **58 model inputs** from 24 raw columns: scaled numbers, the "was missing" indicators, and one column per category value.
- **Be suspicious of the perfect test AUC.** CKD is diagnosed partly from serum creatinine and haemoglobin, which are inputs here. The model is largely rediscovering the diagnostic definition, not predicting something hidden. On 100 test patients, "perfect" also means only that these 100 were easy.

## Step 7: Check every batch before trusting it (src/monitor.py)

```python
"""Check an incoming batch before and after scoring it.

Usage: python -m src.monitor batches/normal.csv
Exit code 1 if the batch should not be trusted.
"""
import json
import sys

import joblib
import pandas as pd
from scipy.stats import ks_2samp

from src.data import FEATURES, NUMERIC

MIN_LAB_COMPLETENESS = 0.5     # a record needs at least half its lab values
MAX_REJECTED_SHARE = 0.10      # more rejected records than this = broken feed
FLAG_RATE_BAND = (0.5, 1.5)    # flag rate must stay within 0.5x-1.5x of baseline

bundle = joblib.load("model/ckd.joblib")
baseline = json.load(open("model/baseline.json"))
reference = pd.read_csv("model/reference.csv")
batch = pd.read_csv(sys.argv[1])[FEATURES]
problems = []

# 1. Completeness guard: imputation must not invent most of a patient.
completeness = batch[NUMERIC].notna().mean(axis=1)
rejected = (completeness < MIN_LAB_COMPLETENESS).mean()
print(f"records: {len(batch)}   below lab-completeness floor: {rejected:.0%}")
if rejected > MAX_REJECTED_SHARE:
    problems.append(f"{rejected:.0%} of records are missing most lab values")

# 2. Drift in values (KS test) and in missingness, per lab.
rows = []
for col in NUMERIC:
    ref, new = reference[col].dropna(), batch[col].dropna()
    p = ks_2samp(ref, new).pvalue if len(new) >= 5 else float("nan")
    miss_delta = batch[col].isna().mean() - baseline["missing_rates"][col]
    rows.append({"lab": col, "ks_p": round(p, 4), "missing_delta": round(miss_delta, 2),
                 "value_drift": p < 0.01, "missing_drift": abs(miss_delta) > 0.15})
drift = pd.DataFrame(rows)
flagged = drift[drift.value_drift | drift.missing_drift]
print(flagged.to_string(index=False) if len(flagged) else "no lab drifted")

# 3. Score the usable records and compare the flag rate with the baseline.
usable = batch[completeness >= MIN_LAB_COMPLETENESS]
if len(usable):
    scores = bundle["pipeline"].predict_proba(usable)[:, 1]
    flag_rate = float((scores >= bundle["threshold"]).mean())
    low, high = (baseline["flag_rate"] * f for f in FLAG_RATE_BAND)
    print(f"flag rate: {flag_rate:.2f}  (baseline {baseline['flag_rate']:.2f}, "
          f"expected {low:.2f}-{high:.2f})")
    if not low <= flag_rate <= high:
        problems.append(f"flag rate {flag_rate:.2f} outside {low:.2f}-{high:.2f}")

print("VERDICT:", "TRUST" if not problems else "HOLD -> " + "; ".join(problems))
sys.exit(1 if problems else 0)
```

Three separate checks, because they catch different problems:

| Check | Question | Catches |
| --- | --- | --- |
| Completeness floor | Does each record have enough real lab values? | Broken feeds, before the model sees them |
| KS test + missing delta | Did lab **values** move? Did **which tests are missing** change? | Population shifts, lab or ordering changes |
| Flag rate band | Is the share of flagged patients normal? | Anything above that slipped through, in either direction |

The **KS test** (Kolmogorov-Smirnov) compares two distributions of one number; a small p-value (below 0.01 here) means they differ.

The guard refuses the batch. **What if there were no guard?** The pipeline would score all 80 patients without a single error, because the imputers fill every blank. And it would flag **95%** of them, against a true CKD rate of 68% in these patients. The model learned "missing labs means sick" (Step 4), so a feed that drops every lab makes everyone look sick. In another dataset the same failure could go the other way: median values look healthy, and nobody gets flagged.

**The general lesson: every mechanism that makes a pipeline tolerant of bad input also makes it silent about bad input.** Anything you impute, default or coerce needs a counter, and a threshold on that counter.

## Step 9: The triage API (app/main.py)

```python
"""CKD triage service: one patient in, risk score and flag out. Refuses mostly-empty records."""
import json
import os
from typing import Optional

import joblib
import pandas as pd
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

from src.data import FEATURES, NUMERIC

bundle = joblib.load(os.environ.get("MODEL_PATH", "model/ckd.joblib"))
PIPE, THRESHOLD = bundle["pipeline"], bundle["threshold"]
MIN_LAB_COMPLETENESS = 0.5

app = FastAPI(title="CKD triage aid")


class Patient(BaseModel):
    # Every field is optional: missing labs are normal. None means "not measured".
    age: Optional[float] = None
    bp: Optional[float] = None
    sg: Optional[float] = None
    al: Optional[float] = None
    su: Optional[float] = None
    bgr: Optional[float] = None
    bu: Optional[float] = None
    sc: Optional[float] = None
    sod: Optional[float] = None
    pot: Optional[float] = None
    hemo: Optional[float] = None
    pcv: Optional[float] = None
    wbcc: Optional[float] = None
    rbcc: Optional[float] = None
    rbc: Optional[str] = None
    pc: Optional[str] = None
    pcc: Optional[str] = None
    ba: Optional[str] = None
    htn: Optional[str] = None
    dm: Optional[str] = None
    cad: Optional[str] = None
    appet: Optional[str] = None
    pe: Optional[str] = None
    ane: Optional[str] = None


@app.get("/health")
def health():
    return {"status": "ok", "threshold": THRESHOLD}


@app.post("/score")
def score(patient: Patient):
    row = pd.DataFrame([patient.model_dump()])[FEATURES]
    completeness = float(row[NUMERIC].notna().mean(axis=1).iloc[0])
    if completeness < MIN_LAB_COMPLETENESS:
        raise HTTPException(422, f"only {completeness:.0%} of lab values present; "
                                 f"need {MIN_LAB_COMPLETENESS:.0%} to score")
    risk = float(PIPE.predict_proba(row)[0, 1])
    result = {"risk": round(risk, 3), "flag": "REVIEW" if risk >= THRESHOLD else "routine",
              "lab_completeness": round(completeness, 2)}
    print(json.dumps({"severity": "INFO", "message": "score", **result}), flush=True)
    return result
```

- **Every field is optional**, unlike Session 7. Missing labs are expected; `None` becomes `NaN`, and the pipeline's imputers handle it.
- **The threshold travels with the model** (`bundle["threshold"]`), not in the code that calls the API. Change the policy, retrain, redeploy; callers never hard-code 0.55.
- **The same completeness floor as the batch monitor**, per request: a record with an empty chemistry panel gets a clear `422` instead of a confident, invented score.
- **One JSON log line per request** feeds the flag-rate monitoring once deployed.

## Common errors and fixes

| Error | Cause | Fix |
| --- | --- | --- |
| A third class `ckd\t` appears | Text values not stripped | Keep the `str.strip()` loop in `load_ckd` |
| `ValueError: Input contains NaN` when scoring | Imputers were fitted outside the saved pipeline | Keep all preprocessing inside `Pipeline` |
| Fewer model inputs than 58 | `add_indicator=True` missing | Add it back; it carries the "missing means sick" signal |
| Threshold looks great on test, worse later | It was chosen on the test set | Choose it on cross-validated **training** scores |
| `FileNotFoundError: model/ckd.joblib` | Model not trained | `python -m src.train` |
| `FileNotFoundError: batches/...` in tests | Batches not created | `python -m src.make_batches` |
| `422 only 0% of lab values present` | Record has no lab values | Expected: the completeness floor is working |
| `ModuleNotFoundError: ucimlrepo` in Cloud Run | `ucimlrepo` imported at module level | Import it inside `load_ckd()`, as in Step 3 |
